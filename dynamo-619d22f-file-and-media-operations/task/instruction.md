Create an executable Python 3 tool at `/app/restore_masters.py`. When run as:

`python3 /app/restore_masters.py /app/session_alpha`

it must repair the session in place, creating `/app/session_alpha/recovered/manifest.json` and one mono 16-bit PCM WAV file per take in `/app/session_alpha/recovered/<take_id>.wav`. The same tool must work for other session directories with the same file formats. After those recovered outputs are written, delete that session's `packets` directory entirely.

Each session has `registry.tsv`, `ledger.tsv`, `trims.tsv`, and packet files under `packets/`. TSV files are tab-separated with a header row. `registry.tsv` columns are `take_id`, `sample_rate`, `total_frames`, `shard_frames`, and `cutoff_tick`. `trims.tsv` columns are `row_id`, `take_id`, `effective_tick`, `head_frames`, and `tail_frames`. For each take, use the trim row with the greatest `effective_tick` that is less than or equal to that take's `cutoff_tick`; if there is no such row, trim zero frames at both ends. Ignore trim rows after the cutoff.

`ledger.tsv` columns are `seq`, `tick`, `action`, and `packet`. A packet is usable for a take only if its latest ledger event with `tick <= cutoff_tick` has `action` equal to `keep`. Ledger rows are not sorted. If two relevant ledger rows for the same packet have the same tick, the larger `seq` is later. Events after the cutoff do not exist for that take.

Packet files begin with ASCII header lines, then one blank line, then a binary payload. The first line is exactly `DYNAMO_AUDIO_PACKET_V1`. Other header fields are `take_id`, `kind`, `index`, `revision`, `codec`, `payload_sha256`, and for parity packets also `members`. Repair-mask packets also have `anchor_sha256`. Validate `payload_sha256` against the encoded payload bytes before decoding; packets with mismatched hashes are ignored. Data packets have `kind=data` and one integer `index`. Parity packets have `kind=parity` and `members` as comma-separated integer indexes. Repair-mask packets have `kind=mask`; their decoded payload is an XOR mask for the data shard named by `index`.

Supported codecs:

`pcm16`: payload bytes are already little-endian signed 16-bit PCM.

`xor_a5`: each payload byte must be XORed with hexadecimal `a5`.

`delta8`: the first sample is a little-endian signed 16-bit value. Each remaining byte is a signed 8-bit delta from the previous sample; clamp nothing, because valid packets never overflow the signed 16-bit range.

For each take and shard index, choose the usable, checksum-valid data packet with the highest `revision`; if revisions tie, choose the lexicographically smallest packet path. Every decoded shard and decoded mask is exactly `shard_frames * 2` bytes, padded with zero bytes beyond the take's `total_frames` when needed. After data-packet selection and before parity recovery, apply at most one usable, checksum-valid repair-mask packet per present data shard: its `index` must match the shard, its `anchor_sha256` must equal the SHA-256 of the currently selected decoded padded shard, and the chosen mask is the highest `revision`, then lexicographically smallest path. Applying a mask means XORing it bytewise with that decoded shard. If a shard is missing, recover it after mask application from usable, checksum-valid parity packets. In each recovery pass, consider every such parity packet whose `members` include exactly one still-missing shard index among the currently known shards. If several parity packets qualify in the same pass, apply only the packet with the highest `revision`, breaking ties by lexicographically smallest path. A parity payload is the bytewise XOR of the final padded decoded data shards for all member indexes. Repeat passes until no qualifying parity packet remains.

Concatenate shards in numeric index order, truncate to `total_frames`, apply the selected head and tail trim in frames, and write a WAV with one channel, 16-bit sample width, and the take's `sample_rate`. The manifest JSON must be UTF-8, two-space indented, with a trailing newline after the closing `}`, and with top-level key `takes`. Its value is a list sorted by `take_id`; each entry has exactly `take_id`, `sample_rate`, `frames`, `pcm_sha256`, `wav_sha256`, `recovered_indexes`, and `audit`. `frames` is after trimming, hashes are lowercase SHA-256 hex strings, and `recovered_indexes` is a sorted list of shard indexes recovered from parity.

`audit` has exactly these keys: `selected_data_packets`, `bad_hash_packets`, `dropped_latest_packets`, `future_ledger_rows`, `repair_masks_applied`, `anchor_rejected_masks`, `parity_packets_used`, `tail_padding_bytes`, and `trim_row_id`. Count selected data packets after revision tie-breaking but before parity; bad-hash packets among usable paths for that take; packet paths for that take whose latest event at or before cutoff is `drop`; ledger rows after cutoff for packets whose header `take_id` matches the take; repair masks actually applied; usable checksum-valid mask packets for the take whose `index` matches a present selected data shard but whose `anchor_sha256` does not match that shard; parity packets actually used to recover a shard; zero-padding bytes removed by the final `total_frames` truncation; and the selected trim row's `row_id`, or an empty string if no trim row applies.
