Build `/app/relay_report.json` for `/app/relayforge/circuit.json` and `/app/replay_relay.py`, a Python 3 tool called as `INPUT_CIRCUIT_JSON OUTPUT_JSON` that writes this schema for any valid Relayforge circuit.

Do not bake in visible answers or constants. Calibration rows are independent one-action examples with exact `pre`, `action`, `event`, `post`, and `score_delta`. Recover circuit-local `hue_bias`, `move_bias`, `take_bias`, `use_bias`, `event_shift[event]`, and `score_shift[event]`. Read each input's `moduli.pulse` and `moduli.focus`.

State is `room`, `pulse`, `focus`, integer `score`, and ordered inventory. Reduce `pulse`/`focus` modulo their moduli whenever state starts or updates. Valid actions: `N/E/S/W`, `REST`, `TAKE item_name`, `USE item_name`.

For a direction, use the current room exit. If present, `gate = (pulse + focus + move_bias[direction] + exit.rune) mod pulse_mod`; `gate >= exit.threshold` emits `moved`, moves to `exit.to`, and sets `pulse = gate + hue_bias[new_room.hue]`, else emits `blocked`, stays put, and sets `pulse = gate + hue_bias[current_room.hue]`. Missing exits emit `wall` and set `pulse = pulse + focus + move_bias[direction] + hue_bias[current_room.hue]`. Reduce each pulse formula modulo `pulse_mod`.

`REST` emits `rested`, adding `hue_bias[current_room.hue]` to pulse. `TAKE x` succeeds only if item `x` is in the room and not held: emit `taken`, add `take_bias + item.weight + hue_bias[item.hue]`, append `x`; else emit `miss_take`, add `take_bias + hue_bias[current_room.hue]`. `USE x` succeeds only if `x` is held: emit `used`, keep it, add `use_bias + item.weight + hue_bias[current_room.hue]`; else emit `miss_use`, add `use_bias + hue_bias[current_room.hue]`. Reduce pulse.

After pulse/room/inventory changes, update focus in the post-action room: `focus = (focus + post_room.echo + event_shift[event]) mod focus_mod`. Then add base score plus `score_shift[event]`. Base scores: `moved=9+pulse+focus-exit.cost`; `blocked=-6+gate-exit.cost`; `wall=-8+pulse`; `rested=pulse-3+(focus mod 3)`; `taken=item.weight*5+pulse+focus+3` when item hue matches pre-action room hue, else `...-2`; `miss_take=-5+pulse`; `used=item.weight+pulse*2+7` when item hue matches current room hue, else `...-3`; `miss_use=-4+focus`.

Output top level: `circuit_id`, `constants`, `calibration_audit`, `results`, `route_solutions`, `surge_solutions`. `circuit_id` is the input string. `constants` has inferred `hue_bias` by `hues`, `move_bias` by `N/E/S/W`, integer `take_bias`, integer `use_bias`, and `event_shift`/`score_shift` by `events`.

`calibration_audit` has integer `row_count`, calibration-row `event_counts` by `events`, integer `score_shift_total`, JSON object list `rows`, and `audit_sha256`. `score_shift_total = sum(score_shift[event] for event in circuit["events"])`: one value per event type, never per calibration row. Each row object has one-indexed `row`, `action`, `event`, `pre_room`, `post_room`, integer `score_delta`, and integer `score_shift`. Only `audit_sha256` uses pipe rows joined with `\n`, no trailing newline: `row_number|action|event|pre_room->post_room|score_delta|score_shift_for_event`.

Quest `results` stay in quest order. Each has `quest_id`, `final_room`, integer `pulse`, integer `focus`, integer `score`, acquisition-order `inventory`, event-name `event_counts`, integer `resonance`, and `trace_sha256`. Quest trace lines: `quest_id|turn_number|action|event|room|pulse|focus|score`.

Below, final state fields mean `final_room`, integer `pulse`, integer `focus`, integer `score`, and acquisition-order `inventory`. `route_solutions` stay in `route_puzzles` order. Choose exactly `turns` actions from `allowed_actions`; repeats and wall/blocked/miss events are legal. Maximize final integer `score`; ties use smallest compact JSON action-list string (array, double quotes, commas, no spaces). Fields: `route_id`, `actions`, final state fields, `event_counts`, `resonance`, `trace_sha256`. Route trace lines replace quest_id with route_id.

`surge_solutions` stay in `surge_puzzles` order. Choose exactly `turns` actions from `allowed_actions`. After each turn, from the post-score state compute `surge = (pulse*7 + focus*11 + event_ordinal*13 + inventory_count*17 + (score mod 19)*19) mod 31`. Track `peak_surge` and immediate-repeat `repeat_count`. Maximize `objective = final score + peak_bonus*peak_surge - repeat_penalty*repeat_count`; ties: higher final score, higher `peak_surge`, then smallest compact JSON action-list string. Frontier audit: each turn processes prior frontier entries sorted by compact JSON action-list string, then `allowed_actions` order; merge key `(room,pulse,focus,inventory,last_action,peak_surge,repeat_count,score mod 19)`; keep higher score then smaller compact JSON action-list string. `frontier_sizes` is kept state count after each turn. `pruned_candidates` counts every merge-discarded candidate, including a replaced incumbent. Fields: `surge_id`, `actions`, integer `objective`, integer `peak_surge`, integer `repeat_count`, integer-list `frontier_sizes`, integer `pruned_candidates`, final state fields, `event_counts`, `resonance`, `trace_sha256`. Surge trace lines are `surge_id|turn_number|action|event|room|pulse|focus|score|surge|peak_surge|repeat_count`.

For quest, route, and surge `resonance`, start at `0` and after each scored action update `resonance = (resonance*131 + turn_number*17 + event_ordinal*37 + pulse*23 + focus*29 + score*31 + inventory_count*41) mod 1000003`. Event ordinals are one-indexed in circuit `events`. Hash UTF-8 trace lines joined with `\n`, no trailing newline.
