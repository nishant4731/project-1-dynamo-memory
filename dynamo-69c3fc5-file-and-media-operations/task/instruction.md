Write an executable Python 3 program at `/app/restore_masters.py`.

It must be runnable as `python3 /app/restore_masters.py INPUT_DIR OUTPUT_DIR`. `INPUT_DIR` contains one directory per session. Each session directory has `session.json`, `ledger.tsv`, and the fragment files named by the ledger. Create `OUTPUT_DIR` if needed. For every session, write a mono 16-bit PCM WAV named `<session_id>.wav` in the output directory and write one combined JSON report named `manifest.json` in that same directory. After a session's WAV is written successfully, delete that session's `fragments` directory tree in place under `INPUT_DIR` (leave `session.json` and `ledger.tsv`).

`session.json` gives `session_id`, `sample_rate`, `master_cutoff_batch`, `master_gain_ppm`, and `frame_grid`. `ledger.tsv` is tab-delimited with columns, in order: `batch`, `slot`, `take`, `revision`, `op`, `path`, `decoded_sha256`, `gain_ppm`, `trim_start`, `trim_end`, and `overlap_next`. Ignore rows with `batch > master_cutoff_batch`. A `RECALL` row invalidates only matching `POST` rows with the same `slot`, `take`, and `revision` whose `batch` is less than or equal to that `RECALL` row's `batch` (and still at or before the cutoff). A later `POST` with the same key and a strictly greater `batch` than every matching in-cutoff `RECALL` remains eligible. For each slot, eligible `POST` rows are those not invalidated, whose fragment decodes successfully, and whose decoded PCM bytes match `decoded_sha256`. Choose the eligible row with highest `revision`; break ties by highest take rank from `/app/take_ranks.tsv` (tab-delimited columns `take` and `rank`; unknown takes have rank `0`), then highest `batch`, then lexicographically smallest `take`.

Fragment format is binary. Bytes 0-3 are `SPL1`; byte 4 is codec (`0` raw little-endian int16 samples, `1` first int16 sample followed by signed int8 deltas); byte 5 flags; bytes 6-7 are little-endian frame count. After codec decoding, if flag bit 0 is set, reverse the samples; if bit 1 is set, invert polarity by negating samples with `-32768` clamped to `32767`. The checksum is over the resulting int16 little-endian PCM before trim or gain.

For a chosen row, drop `trim_start` frames from the front and `trim_end` frames from the back, then multiply each sample by `gain_ppm / 1000000`. Round halves away from zero and clamp to signed 16-bit range. If trim removes the entire fragment (`trim_start + trim_end >= decoded frame count`), discard that chosen row for assembly: the slot has no selected fragment, and count it under `trim_empty_slots` as well as `empty_slots`. If a slot has no eligible `POST`, omit that slot from the master. Assemble remaining eligible slots in ascending numeric `slot`.

When appending the next assembled slot immediately after a previous assembled slot whose numeric `slot` values differ by exactly `1`, crossfade `N = min(previous.overlap_next, current_length, next_length)` frames, where `current_length` is the frame count of the already-assembled master PCM before this append and `next_length` is the incoming slot's frame count after trim and fragment gain. For each frame index `i` in `0 .. N-1`, use integer weights `old_weight = (N - i) * (N - i) * (N + 2 * i + 1)` and `new_weight = (i + 1) * (i + 1) * (3 * N - 2 * i)`, then replace the old sample with `round_half_away(old * old_weight + new * new_weight, old_weight + new_weight)` clamped to signed 16-bit. Append any remaining new frames after the overlap. Count `overlap_limited_frames` as the total amount by which declared overlaps exceed actual crossfade `N` on those adjacent transitions, and count one `adjacent_crossfades`. If consecutive assembled slot numbers differ by more than `1` (an empty-slot gap), do not crossfade: append the new body with a hard join, add the full `previous.overlap_next` into `overlap_limited_frames`, and count one `gap_hard_joins`. Worked numeric examples of the adjacent-slot crossfade weights are in `/app/crossfade_examples.tsv`.

After assembly and before master gain, if `frame_grid > 0` and the master length is not a multiple of `frame_grid`, append zero samples until the length is the next multiple of `frame_grid`. Count those added zeros as `grid_pad_frames`. Then multiply the full master by `master_gain_ppm / 1000000` using the same half-away rounding and signed 16-bit clamp. Count `master_gain_clip_samples` on that final pass only, after rounding and before clamping. Fragment `gain_clip_samples` are counted earlier, before crossfade, and never include master-gain clips. Each WAV must be mono 16-bit PCM at the session `sample_rate`.

`manifest.json` must be UTF-8 JSON with keys `version` and `sessions`. Use `version: 1`. `sessions` is sorted by `session_id`. Each session object has `session_id`, `sample_rate`, `frames`, `sha256`, `used_fragments`, and `ignored`. `sha256` is the hex SHA-256 of final WAV PCM bytes, not the WAV container. `used_fragments` is sorted by slot and contains `slot`, `take`, `revision`, `path`, and `frames_after_trim`. `ignored` contains integer counts for `future_rows`, `recalls`, `checksum_rejects`, `superseded_posts`, `empty_slots`, `trim_empty_slots`, `overlap_limited_frames`, `adjacent_crossfades`, `gap_hard_joins`, `grid_pad_frames`, `gain_clip_samples`, and `master_gain_clip_samples`. Count `checksum_rejects` only for unrecalled in-cutoff `POST` rows that fail decode or checksum. Count `superseded_posts` as valid eligible posts that were not selected. Count `empty_slots` as slot numbers from `1` through the largest in-cutoff ledger `slot` that have no selected fragment after trim-empty discards. Count `trim_empty_slots` as chosen eligible posts discarded because trim left zero frames. Count `gain_clip_samples` before crossfade, after rounding fragment gain but before int16 clamping. Count `master_gain_clip_samples` only on the final master-gain pass.
