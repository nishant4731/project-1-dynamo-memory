This packet uses the Prism Relay renderer profile. The agent-visible calibration cases in `/app/data/calibration/case_*/` contain `scene.json`, the expected `final.ppm`, and the expected `report.json` generated by this same profile. The profile is a compact integer renderer: recover the tile base colors for non-digit tiles and four 3x3 glyph masks from those cases. The probes intentionally mix heated cells, decorated tiles, flares, and actor overlays; recover the constants by applying the formulas below rather than by assuming a zero-heat isolated tile or blank actor background. Profile hue colors are fixed as `red=(226,55,60)`, `cyan=(45,207,218)`, `gold=(239,187,54)`, and `violet=(174,91,224)`. The formulas and ordering below are fixed for every scene.

Scenes are JSON objects with integer `width`, `height`, `ticks`, `tiles`, `actors`, `events`, optional `flares`, and optional `analysis`. `tiles` is a height-length array of width-length strings. Tile characters are `.`, `#`, `~`, `^`, `*`, `+`, `/`, `\`, and decimal digit tiles. A digit label forms an active portal pair only when that same digit appears exactly twice in the board; a digit label that appears once is an inert digit tile for movement, heat bias, stamping, flares, and rendering. Actors have string `id`, `glyph`, `hue`, integer `x`, `y`, `energy`, integer `phase`, and `dir` in `N,E,S,W`. Events are sorted and applied by `(tick, event-type priority, actor string, seq)` before movement for that tick. Event-type priority is `swap`, `turn`, `pulse`, `stamp`. `turn` sets an actor direction. `pulse` adds `delta` to energy and clamps to `[0,9]`. `swap` exchanges positions for the two named actors and increments `swaps`. `stamp` adds `amount` heat to any in-bounds board cell and increments `stamps`; walls (`#`) and digit tiles are valid stamp targets.

Tile heat bias is `.` 0, `#` -3, `~` -2, `^` 3, `*` 1, `+` 2, `/` 1, and `\` 1; digit tiles have heat bias 0. Actors are processed each tick by ascending `id`. At their origin, add `max(0, energy + tile_heat_bias + phase)` heat, clamp heat to `[0,63]`, and increment `heat_writes`. Then attempt one step in the current direction. Out-of-bounds, `#`, or a wall target keeps the actor in place, reverses direction (`N<->S`, `E<->W`), subtracts 2 energy clamped to `[0,9]`, and increments `bounces`. Otherwise the actor moves. A `/` tile turns `N->E`, `E->N`, `S->W`, `W->S`; a `\` tile turns `N->W`, `W->N`, `S->E`, `E->S`. A `*` tile sets `phase = (phase + energy + tick) mod 4`, then adds prism shift `[3,-2,4,-1][phase]` to energy clamped to `[0,9]`, and increments `prism_shifts`. If the destination tile is a digit whose label appears exactly twice, teleport the actor to the other same-digit cell sorted by `(y,x)`, set `phase = (phase + digit + tick) mod 4`, and increment `portal_uses`; if that label appears once, leave the actor on the digit tile and do not increment `portal_uses`. After any successful move, add `1 + phase` heat at the destination, clamp, and increment `heat_writes`.

After all actors move in a tick, actors sharing a cell collide. Collision groups are processed by `(y,x)` and actors inside a group by `id`. Within each sorted collision group, `group_index` is the actor's zero-based index: the first actor by `id` has `group_index = 0`, the second has `group_index = 1`, and so on. Each group increments `collisions`, adds `sum(energy) * group_size` heat to its cell, and updates each actor to `energy = clamp(total_energy - old_energy + group_index,0,9)` and `phase = (phase + group_index + group_size) mod 4`.

After collisions, process optional `flares` sorted by `(y,x,id)`. A flare has string `id` and integer `x,y,start,period,radius,strength`; valid scenes use in-bounds anchors, positive `period`, and nonnegative `radius`. On tick `t`, a flare is active only when `t >= start` and `(t-start) mod period == 0`. When active, read the current heat at its anchor after any earlier same-tick flares, set `base = clamp(strength + anchor_heat // 6,0,24)`, increment `flare_pulses`, and visit all in-bounds cells with Manhattan distance at most `radius`. For each visited cell, compute `delta = base - distance*3`; when `delta > 0`, add it to that cell's heat with clamp `[0,63]` and increment `flare_writes`. Flares can write walls and digit cells.

The final canvas is PPM P6 with dimensions `width*3` by `height*3`. Each board cell is a 3x3 block. Cell color starts from the profile base color for that tile; digit tile `d` starts from `(34 + 17*d, 35 + 9*d, 92 + 13*d)`. Add `(heat*5, heat*3, heat*7)` with channel clamp to `[0,255]`. In every cell-rendering and glyph-rendering rule, `px` and `py` are the local 0, 1, or 2 pixel offsets inside that cell's 3x3 block, not final-canvas coordinates. `+` cells brighten pixels whose `(px+py+heat)` is even by adding 18 to each channel with clamp. Digit cells brighten corner pixels by adding 12 to red and 20 to blue with clamp. Actors render after all cells, sorted by `(y,x,id)`. For glyph-mask pixels, set `alpha = clamp(92 + energy*13 + phase*7,0,244)`, tint the profile hue as `(r + phase*9, g - phase*5, b + phase*7)` with clamp, and blend each channel by `(base*(255-alpha) + tint*alpha) // 255`. Non-mask shadow pixels darken each channel by 16 only when `(px+py+phase) mod 5 == 0`.

`report.json` is a JSON object with keys `schema`, `canvas`, `tick_count`, `actors`, and `counters`. `schema` is integer `1`. `canvas` records integer `width` and `height` for the final PPM canvas, not the board grid. `actors` is sorted by `id` and records `id,x,y,dir,energy,phase,hue`. `counters` contains `bounces,collisions,flare_pulses,flare_writes,heat_writes,portal_uses,prism_shifts,stamps,swaps,lit_cells,peak_heat,image_checksum`. `lit_cells` is the number of board cells whose final heat is greater than 0. `peak_heat` is the maximum final board-cell heat, or 0 for an empty heat grid. For 0-indexed final-canvas pixel `(x,y)` with RGB channels `(r,g,b)` and top-left origin, `image_checksum = (sum((x+1)*3*r + (y+1)*5*g + (x+y+2)*7*b for every pixel) mod 1000000007)`.

`forecast.json` is computed after the baseline `final.ppm` and `report.json`; forecast trials must not mutate those baseline artifacts. If `analysis` is missing, use an empty candidate set. Otherwise `analysis.probe_ticks` is a list of integer ticks, `analysis.amounts` is a list of signed integer heat amounts, and `analysis.include_walls` is a boolean. First deduplicate and sort probe ticks ascending, discarding ticks outside `[0,ticks-1]`. Candidate cells are all board cells sorted by `(y,x)`, except skip `#` cells when `include_walls` is false. Candidate stamps are the Cartesian product of sorted ticks, candidate cells, and amounts in their listed order. For each candidate, run a fresh replay with one hypothetical stamp applied at the start of that candidate tick before ordinary events; it adds signed `amount` heat with clamp `[0,63]` and increments `stamps`, but it does not appear in `events`. Render and report that trial normally, then compute `score = (image_checksum + 97*lit_cells + 193*peak_heat + 389*portal_uses + 577*collisions + actor_term) mod 1000000007`, where `actor_term = sum((i+1)*(x + 3*y + 5*energy + 7*phase) for actors sorted by id with zero-based index i)`. Choose the candidate with maximum `(score, -tick, -y, -x, -amount)`. `forecast.json` has integer `schema` 1, integer `candidate_count`, `baseline` with integer `image_checksum,lit_cells,peak_heat` copied from baseline `report.json`, and `best`. `best` is null when there are no candidates; otherwise it records integer `tick,x,y,amount,score,image_checksum,lit_cells,peak_heat,portal_uses,collisions` for the chosen trial.
