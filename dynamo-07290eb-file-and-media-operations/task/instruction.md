Ship one executable Python script at `/app/restore_metadata.py`. It takes a single argument, `PACKAGE_ROOT`, and may repair only that directory tree. After installing it, run it once against `/app/data/package`; copy the resulting `repair_report.json`, `restored_manifest.jsonl`, and `event_trace.jsonl` to `/app/repair_report.json`, `/app/restored_manifest.jsonl`, and `/app/event_trace.jsonl`. None of those four `/app` paths may be symlinks.

The archive root contains `manifest.json`, `FORMAT_NOTES.txt`, object payloads in `input/objects/`, and JSONL journals in `input/ledger/`. The manifest gives the asset list, each asset type (`file` or `dir`), file source names, mode profile table, and `ledger_salt`. A journal row is trusted only if its `mac` is the BLAKE2s digest with `digest_size=16`, keyed by UTF-8 `ledger_salt`, over the row after removing `mac` and encoding it as JSON with sorted keys and compact separators.

State replay:

- For each asset and each single-valued kind (`path`, `profile`, `mtime`, `retire`, `basename_patch`), choose the trusted row with the largest `(clock, seq, row_id)`.
- A chosen retire value equal to `{"retired": true}` means the asset produces no restored entry.
- Permission replay starts from the chosen profile, or from the `standard` profile if no trusted profile row was chosen. If there is no trusted profile row, treat the profile boundary as before every trusted chmod row for that asset, so all trusted chmod rows apply. Then process trusted `chmod` rows that are later than that profile boundary, sorted ascending by `(clock, seq, row_id)`. Token items that are not strings of `+` or `-` followed by `u+r`, `u+w`, `u+x`, `g+r`, `g+w`, `g+x`, `o+r`, `o+w`, `o+x`, or `sticky` are ignored for mode math, but their trusted chmod row still appears in `applied_chmod_rows`. File results are masked to `0777`; directory results may retain sticky.
- Mtime ticks are converted through trusted `clock_anchor` rows. Each anchor has `clock_id`, integer `tick`, and integer `mtime_ns`; for each clock, use the trusted minimum tick and trusted maximum tick in `low_mtime_ns + (tick - low_tick) * (high_mtime_ns - low_mtime_ns) // (high_tick - low_tick)`.
- A usable path value is a nonempty JSON array of strings. Reject it when any segment is empty, `.`, `..`, contains `/`, contains NUL, or is not a string.
- A basename patch is considered only after the path is usable and only when its selected value is active with string fields `prefix` and `suffix`. Replace the last segment by `prefix + old_name + suffix`. Inactive patches and active patches with non-string fields are ignored. If an active string patch creates an invalid basename, the asset becomes unsafe.
- Unsafe files are emitted as `quarantine/<asset>.blob` with mode `0600`; unsafe directories are omitted. Quarantine files keep the selected mtime row's clock-anchor-interpolated nanosecond timestamp in both the filesystem and `final_mtime_ns`. Quarantine does not add to `restored_files`, and an unsafe patched basename does not add to `patched_assets`.
- Among non-quarantine outputs whose relative paths match under Python `casefold()`, keep the one with highest final mtime, breaking ties by lowest asset id. Rename each loser with `~sha256(asset)[:6]` before the last extension. For a leading-dot name with no other dot, append that suffix to the end.

Filesystem effects: recreate `PACKAGE_ROOT/restored`, copy file bytes from `input/objects`, create required parents, set final modes and nanosecond mtimes on restored files, quarantine files, and explicit directory assets, and stamp directory mtimes after children exist. When the outputs have been written successfully, delete both `input/ledger` and `input/objects`.

Write exact output formats:

- `repair_report.json`: compact JSON object with exactly `schema`, `assets_seen`, `valid_events`, `invalid_events`, `restored_files`, `restored_dirs`, `retired_assets`, `unsafe_path_assets`, `quarantined_assets`, `patched_assets`, `collision_renames`, `final_modes`, `final_mtime_ns`. `schema` is `1`. Only the five fields ending in counts conceptually (`assets_seen`, `valid_events`, `invalid_events`, `restored_files`, `restored_dirs`) are integers. Asset-id arrays are sorted. `collision_renames` is sorted by `asset` and each row has `asset`, `from`, `to`. `final_modes` uses four-digit octal strings keyed by restored path; `final_mtime_ns` uses integer nanoseconds keyed the same way.
- `restored_manifest.jsonl`: compact UTF-8 JSON Lines, no blank lines, sorted by `(path, asset)`. Include one row per non-quarantine restored file, quarantined file, or explicit directory with exactly `asset`, `path`, `type`, `mode`, `mtime_ns`, `sha256`; `mode` is a four-digit octal string and directory `sha256` is `null`.
- `event_trace.jsonl`: compact UTF-8 JSON Lines, no blank lines, sorted by `asset`. Include one row per manifest asset with exactly `asset`, `type`, `disposition`, `final_path`, `selected_rows`, `applied_chmod_rows`. `disposition` is one of `restored`, `quarantined`, `retired`, `omitted_unsafe_dir`; `final_path` is a relative restored/quarantine path or `null`. `selected_rows` contains exactly `path`, `profile`, `mtime`, `retire`, `basename_patch`, each holding the selected row id or `null`. `applied_chmod_rows` is the ordered list of chmod row ids used for that asset.
