Build an interpretability inspection tool for the sparse-feature probe pack in `/app/data/atlas_pack`.

Create an executable Python 3 script at `/app/inspect_atlas.py`. It must accept exactly two arguments, an input pack directory and an output directory. Run it once as:

`/app/inspect_atlas.py /app/data/atlas_pack /app/output`

The input pack contains `manifest.json`, `features.csv`, `profiles.csv`, `terms.csv`, `observations.csv`, and `README.txt`. The `manifest.json` field `concept_order` is the canonical concept order. `features.csv` gives integer `center`, `gain`, `polarity`, `min_raw`, `max_raw`, and `edit_cost` for every feature. `profiles.csv` gives candidate probe-profile rows with `profile_id,feature_id,raw_offset,gain_multiplier`; every complete profile has exactly one row for every feature. Each observation row has `record_id,trace_id,split,known_at,revision,status,payload_sha256,payload_json`. A row is checksum-valid only when `payload_sha256` equals the SHA-256 hex digest of the UTF-8 bytes of `payload_json` exactly as stored. Checksum-invalid rows are counted as checksum rejects before any other handling. Valid rows with `status=retired` are counted as retired and never selected. For every `trace_id`, select the valid active row with greatest `(known_at, revision, record_id)`, comparing the first two as integers and `record_id` lexicographically. Other valid active rows for that trace are superseded. Selected rows with `split=calibration` contain payload `scores`; selected rows with `split=target` omit scores.

Recover the active probe profile and the pack-specific integer coefficient for every concept and every term from the selected calibration rows. For a candidate profile, a feature's normalized value is `(raw_activation + raw_offset - center) * gain * polarity * gain_multiplier`, using raw activation `0` when a feature id is missing from the payload. For `terms.csv`: `bias` has raw value `1`; `linear` uses normalized `feature_a`; `hinge` is `max(0, normalized feature_a - threshold)`; `pair_product` is `normalized feature_a * normalized feature_b`. Multiply the raw value by integer `scale`. For each concept, the score is the sum over all terms of `term_value * coefficient`. Select the unique complete `profile_id` for which the selected calibration rows admit exact integer coefficient vectors that reproduce every selected calibration score exactly. Calibration rows may be redundant or linearly dependent; do not assume a fixed prefix is independent.

For each selected target row, score every concept. The label is the highest score, with `concept_order` as the tie-break. The runner-up is the second concept under the same ordering. `margin` is `label_score - runner_up_score`. The target rows in all outputs are ordered by `trace_id` ascending. `top_terms` for the winning label are the first four terms sorted by descending absolute contribution, then `term_id` ascending; include the bias term if it ranks in the first four.

Also compute counterfactual edit plans. Consider selected targets in ascending `(margin, trace_id)` order and keep the first five targets that have at least one legal flip plan. A legal plan changes one to three features. For each changed feature, choose an integer `to_raw` within both `[min_raw, max_raw]` and `current_raw - 3` through `current_raw + 3`, excluding the unchanged value; `current_raw` is the payload activation or `0` when missing. The plan must make the post-edit top label differ from the base label under the same scoring and tie-break rules. Its cost is `sum(edit_cost * abs(to_raw - current_raw))`. For each plan, compute `weakest_revert_margin` by reverting exactly one edited feature at a time while keeping the other edits, scoring each reverted trace, and taking the minimum `counterfactual_label_score - base_label_score`; for one-edit plans, this is the base trace's margin for the counterfactual label against the base label. Choose the plan with minimum cost; ties choose the highest `weakest_revert_margin`, then highest post-edit margin, then fewer edited features, then the lexicographically smallest edit string after sorting edits by `feature_id`. An edit string item is `feature_id:from_raw->to_raw`, joined with semicolons. In JSON edit objects, `delta` is signed exactly as `to_raw - from_raw`, not an absolute value.

Write exactly these files:

`/app/output/inspection_summary.json`: compact JSON with one trailing newline. Use sorted object keys. Schema: `pack_id`, `profile_id`, `concept_order`, `term_order`, `coefficients`, `record_audit`, `targets`, `interventions`. `profile_id` is the selected active probe profile. `coefficients` maps each concept to every `term_id` integer. `record_audit` has integer fields `rows_total`, `checksum_rejects`, `retired_rows`, `superseded_valid_rows`, `selected_calibration`, and `selected_targets`. Each target object has `trace_id`, `label`, `scores`, `runner_up`, `margin`, and `top_terms`; each top term has `term_id`, `kind`, `value`, `coefficient`, and `contribution`, all integers except ids/kind. Each intervention has `trace_id`, `base_label`, `base_score`, `counterfactual_label`, `counterfactual_score`, `runner_up`, `margin`, `weakest_revert_margin`, `cost`, and `edits`; each edit has `feature_id`, `from_raw`, `to_raw`, signed `delta`, and `cost`.

`/app/output/target_assignments.csv`: header `trace_id,label,score,runner_up,margin,top_terms`. One row per selected target. `score` is the winning score. `top_terms` is the same four winning-label terms encoded as `term_id=contribution` joined with semicolons.

`/app/output/counterfactual_plans.csv`: header `trace_id,base_label,base_score,counterfactual_label,counterfactual_score,runner_up,margin,weakest_revert_margin,cost,edits`. One row per retained intervention target in the selected `(margin, trace_id)` order.
