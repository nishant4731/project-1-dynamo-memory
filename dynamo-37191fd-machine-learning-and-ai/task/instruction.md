Create `/app/audit_rulebook.py`, a self-contained Python CLI for sparse-feature audit bundles. Run it on `/app/data/visible` and write `/app/output`. The CLI takes exactly input bundle directory and output directory and must remain at `/app/audit_rulebook.py` for hidden runs.

Each bundle has six TSVs: `source_quality.tsv`, `method_profile_offsets.tsv`, `calibration.tsv`, `calibration_labels.tsv`, `candidates.tsv`, and `handoff_links.tsv`. Valid profiles are `bridge`, `cortex`, and `guard`. `source_quality.tsv` maps source to integer `bonus`; `method_profile_offsets.tsv` has `profile`, `source`, integer `offset`. Every feature-row source is defined in both.

`calibration.tsv` and `candidates.tsv` share row fields `record_id`, `feature_id`, `profile`, `source`, `revision`, `quality`, `activation`, `frequency`, `patch_delta`, `ablate_delta`, `margin`, `purity`, `stability`, `edge_in`, and `edge_out`. A feature row is invalid when it has missing or extra fields, blank `record_id`/`feature_id`, unknown profile/source, any missing or non-integer numeric field, `quality` outside 0..100, `activation` outside 0..120, `frequency` outside 0..240, `purity` or `stability` outside 0..100, or a negative edge count. Invalid candidate rows are excluded and counted. For duplicate valid rows with the same `feature_id`, keep the row with greatest `revision`, then greatest `quality`, then lexicographically greatest `record_id`; each other valid candidate row for that feature counts as a duplicate.

Use selected calibration rows plus `calibration_labels.tsv` to infer one global parameter set and one set per profile. A label row gives `selected_record_id`, integer `score`, `label`, and semicolon-separated `reasons` for the deduplicated calibration row. The labels identify a unique solution in these domains:

- Global: `patch_weight` 1..8, `ablate_weight` 1..8, `margin_weight` 0..6, `stability_weight` 0..5, `freq_divisor` 12..42.
- Per profile: `bias` -24..24, `core_threshold` 60..94, `relay_threshold` 32..66, `dead_activation_max` 4..18, `purity_cut` 50..90.

For any selected feature row, compute:
`score = clamp(-120, 220, bias + source_bonus + method_profile_offset + patch_weight*patch_delta + ablate_weight*ablate_delta + margin_weight*margin + stability_weight*(stability-50) + 4*edge_out - 3*edge_in + purity_term - frequency_penalty)`.
`purity_term` is 8 if `purity >= purity_cut`, otherwise -7. `frequency_penalty` is `max(0, frequency-40) // freq_divisor` with floor integer division.

Assign labels by the first matching rule: `dead` if `activation <= dead_activation_max` or `stability < 25`; else `core` if `score >= core_threshold`, `purity >= purity_cut`, `patch_delta > 0`, and `ablate_delta > 0`; else `relay` if `score >= relay_threshold`, `edge_out > edge_in`, and `patch_delta >= 0`; else `spurious` if `score <= -35`, `patch_delta*ablate_delta < 0`, or `purity < 35`; otherwise `background`.

Reasons are ordered exactly. `dead` includes `low_activation` if that condition fired, then `unstable` if fired. `core` uses `["strong_direct_effect","clean_probe"]`; `relay` uses `["outgoing_mediator"]`. `spurious` includes `negative_or_conflicted_effect` if the score/conflict condition fired, then `low_purity` if fired. `background` uses `["default_band"]`.

`handoff_links.tsv` fields are `from_feature_id`, `to_feature_id`, `channel`, `strength`, and `lag`. Channels `probe`, `patch`, `ablate` have bonuses 0, 4, -2. A link is invalid for missing/extra fields, endpoint not selected from `candidates.tsv`, self-loop, unknown channel, non-integer `strength`/`lag`, `strength` outside 1..30, or `lag` outside 0..8. Valid links may cross profiles, but routes may not.

After labeling candidates, write `/app/output/handoff_routes.jsonl`. For each profile, choose the best simple directed 1..4-link route that starts at `core`, ends at same-profile `spurious` or `dead`, and uses only same-profile `relay` intermediates. Link value is `strength - 2*lag + channel_bonus`; route score is `start_score - terminal_score + sum(link_values) - 5*(link_count-1)`. Tie-break by highest score, fewer links, smallest `>`-joined path, then smallest joined channels. For the chosen route, remove each route link once and recompute that profile's best route. `critical_link` is the removal with largest `score_loss`; no fallback means `fallback_path:null`, `fallback_route_score:null`, `score_loss=original_route_score+1000`. Tie critical links by smallest `from>to>channel`. Route rows have exactly `profile`, `start_feature_id`, `terminal_feature_id`, `terminal_label`, `path`, `route_score`, `link_count`, `channels`, `critical_link`. `path`, `channels`, and non-null `critical_link.fallback_path` are JSON arrays of strings (native JSON arrays, not a single JSON-encoded string). `critical_link` has exactly `from_feature_id`, `to_feature_id`, `channel`, `fallback_path`, `fallback_route_score`, `score_loss`.

Write `/app/output/audit_labels.jsonl` as selected candidates sorted by `feature_id`, with exactly `feature_id`, `selected_record_id`, `profile`, `score`, `label`, `reasons`. Write `/app/output/rulebook_summary.json` with exactly `candidate_rows`, `invalid_rows`, `duplicate_rows`, `link_rows`, `invalid_link_rows`, `route_count`, `selected_features`, `labels`, `learned_global`, `learned_profiles`. `candidate_rows` and `link_rows` count all data rows in their TSVs. `labels` has integer counts for all five labels. `learned_global` has the five global keys. `learned_profiles` is keyed by `bridge`, `cortex`, `guard`, with the five profile keys each. Counts and scores are JSON integers. Bundles are sized so constraint-based code finishes within 30 seconds; exhaustive Cartesian search over every profile range is not expected to finish.
