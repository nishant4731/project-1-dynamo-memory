Build `/app/solver.py` and `/app/answer.json` for Embermaze Flux.

Run contract: `python3 /app/solver.py INPUT_JSON OUTPUT_JSON`. Read a scenario JSON and its JSONL calibration from `calibration_path` (relative unless absolute), recover integer constants, simulate all commands, and write the report to `OUTPUT_JSON`. Also solve `/app/data/scenario.json` into `/app/answer.json`.

State: integer `x,y,energy,phase,score,load`, key counts `red/green/blue`, sparse `heat` keyed `"x,y"` (missing is 0). Commands: `N/E/S/W/WAIT`. Cells: `. ~ ^ : r g b R G B 0 1 *` plus wall `#`; lowercase keys, uppercase gates, each portal digit exactly two cells.

Calibration movement rows contain `probe,before,after,command,cell,event,heat_before,world.rows`; probes: `terrain_zero`, `terrain_hot`, `action`, `key`, `gate_open`, `gate_deny`, `portal_fire`, `beacon`, `blocked`. Flux probes `flux_low/high` contain `before,after,tick,lane`. Recover `action_cost/phase` (`WAIT=0`), per-cell `terrain_cost/phase/score`, `heat_gain`, `heat_weight`, per-color `key_gain`, `gate_threshold`, `deny_cost/penalty/phase`, per-digit `portal_parity/load`, `beacon_load`, per-direction `block_cost/phase`, `block_penalty`, and global `flux_cost/score/weight/phase/heat/load`.

Movement: target current cell for `WAIT`, else adjacent. If non-`WAIT` target is outside grid or `#`, leave position/heat unchanged; apply `energy -= block_cost[command] + phase % 2`; `score -= block_penalty`; `phase = (phase + block_phase[command] + load) % 17`; increment `bumps`; event `blocked`.

Otherwise let `h = heat[target]`. If target is a gate and key count is 0 or `energy < gate_threshold[color] + h`, deny: no movement/heat change; `energy -= deny_cost[color] + phase % 3`; `score -= deny_penalty[color]`; `phase = (phase + deny_phase[color] + h) % 17`; increment `gate_denied`; event `gate_denied`.

Successful entry applies `energy -= action_cost[command] + terrain_cost[cell] + ((phase + load + h) % 4)`; `phase = (phase + action_phase[command] + terrain_phase[cell] + load + h) % 17`; `score += terrain_score[cell] + h * heat_weight[cell] + phase`; move; `heat[target] = h + heat_gain[cell]`; increment `waits` for `WAIT`, else `moves`; event starts `wait` or `move`.

Then cell effects: key cells add `key_gain[color] + phase % 2`, increment `keys_found`, event `key`; opened gates consume one key, event `gate_opened`; portal fires when `(phase + h) % 2 == portal_parity[digit]`, moves to the other digit cell, adds `portal_load[digit] + h` to `load`, increments `portals`, event `portal`; beacon sets `load = (load + beacon_load + heat[current] + phase) % 11`, increments `beacons`, event `beacon`.

Initialize `visited` with the starting `[x,y]`; after each command, append post-command position only if new. Portals contribute only the post-teleport cell. Update `trace_digest = (trace_digest*131 + (x+7)*17 + (y+11)*19 + energy*3 + phase*5 + score + load*23 + event_code*29) % 1000000007`, codes move=1, wait=2, blocked=3, gate_denied=4, gate_opened=5, key=6, portal=7, beacon=8.

Next process same-tick `echoes`, sorted by string `id`. Echo fires when position is within Manhattan `radius` of `source` and `(phase + load + heat[source] + tick) % mod == residue`. On fire: `signal = heat[source] + phase + load + tick`; `energy += energy_scale * signal`; `score += score_scale * (signal + heat[target])`; `heat[target] += heat_add + signal % 3`; `load = (load + load_add + heat[target]) % 13`; increment `echoes`; update `sidecar_digest = (sidecar_digest*137 + tick*31 + (source_x+5)*17 + (source_y+7)*19 + signal*23 + load*29 + heat[target]*31 + 1) % 1000000007`.

Finally process same-tick `flux_lanes`, sorted by string `id`. A lane covers row `y == line` or column `x == line`, with inclusive `lo/hi` on the other coordinate. It fires when covered and `signal % span == residue`, where `signal = heat[anchor] + load + tick + offset`. On fire: `energy -= flux_cost + signal % 5`; `score += flux_score + signal * flux_weight`; `phase = (phase + flux_phase + signal) % 19`; `heat[target] += flux_heat + phase % 3`; `load = (load*2 + flux_load + heat[target]) % 17`; increment `fluxes`; update `sidecar_digest = (sidecar_digest*137 + tick*31 + (target_x+5)*17 + (target_y+7)*19 + signal*23 + load*29 + heat[target]*31 + phase*37 + 2) % 1000000007`. Echoes and fluxes never edit `visited` or `trace_digest`.

Output exactly one JSON object: `final` (`x,y,energy,phase,score,load,keys`), `checksum`, `counters` (`moves,waits,bumps,gate_denied,gate_opened,keys_found,portals,beacons,echoes,fluxes`), `trace_digest`, `sidecar_digest`, `visited`, `heat`. `heat` follows `report_cells` as `{"x":X,"y":Y,"value":V}`. `checksum = (score*97 + energy*31 + phase*17 + load*13 + x*7 + y*11 + red_keys*101 + green_keys*103 + blue_keys*107 + echoes*109 + fluxes*113 + sidecar_digest*127 + trace_digest) % 1000000007`.
