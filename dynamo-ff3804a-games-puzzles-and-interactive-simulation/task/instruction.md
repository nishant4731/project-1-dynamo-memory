Build a reusable solver for the calibration card game in `/app/data`.

The input directory contains `/app/data/calibration.jsonl` and `/app/data/puzzles.json`. Calibration rows are finished replays from the same engine used by the puzzles. Each row has a starting `charge`, a rectangular `board`, a `hand`, a fixed `script`, and a final `result`. Puzzle queries have the same board and hand schema but no script.

The engine has glyphs `A`, `B`, `C`, `D`, terrains `.`, `~`, `^`, `*`, and blocked cells `#`. Profile constants are not printed directly; infer them from calibration. The family is fixed: `.` has terrain score bias `0` and terrain drift `0`; each glyph has an integer weight and a drift in `0` through `10`; every non-blocked terrain has an integer score bias and a drift in `0` through `10`; each ordered previous/current glyph pair has an integer pair bonus; and one integer `anchor_bonus` is added when a placement cell is orthogonally adjacent to at least one `#` cell. Calibration includes single-card terrain probes, pulse drift probes, non-dot terrain pulse probes, ordered adjacent-pair probes, and `#`-adjacent anchor probes that identify the profile.

Rows with `kind` `pulse` are fixed-script replays where a later move has a forced pulse with a same-row occupied count, a same-column occupied count, or both. Use the same engine rules; they pin exact glyph drift, not only drift modulo the charge cycle, and exercise both coefficients in `row_count + 2 * col_count`. Rows with `kind` `terrain_pulse` are consistency checks that force a later pulse on `~`, `^`, or `*`, so recovered terrain drift must keep charge updates and pulse scoring consistent. Ordered pair probes include both lower and higher previous-card ranks, identifying the link multiplier as `min(p.rank, r)`. Rows with `kind` `anchor` are single-move probes on a cell next to `#` that pin `anchor_bonus`.

Cards are played in hand order. A move places the current card on an empty non-`#` cell. Orthogonal neighbors already containing cards form links. For a card with glyph `g`, rank `r`, terrain `t`, current charge `c`, linked previous cards `p`, and before-move row/column occupied counts `row_count` and `col_count`, the move delta is:
`r * glyph_weight[g] + terrain_bias[t] + c + sum(pair_bonus[p.glyph][g] * min(p.rank, r) for each link) + pulse + anchor`.
The pulse term is `glyph_drift[g] * (row_count + 2 * col_count)` exactly when `(c + terrain_drift[t] + r) % 5 == 0`; otherwise `0`. Count one pulse whenever that condition is true, even if the term is zero. The anchor term is `anchor_bonus` when the chosen cell is orthogonally adjacent to at least one `#` cell; otherwise `0`.

After scoring, update charge to `(c + glyph_drift[g] + terrain_drift[t] + r + link_count) % 11`. Update signature after each move as `(old_signature * 131 + (row + 1) * 17 + (col + 1) * 19 + rank * 23 + glyph_index * 29 + delta * 31 + new_charge * 37) % 1000000007`, with `glyph_index` `A=0`, `B=1`, `C=2`, `D=3`. Start charge, score, links, pulses, and signature from query fields when present; otherwise each starts at zero.

For each query in `/app/data/puzzles.json`, choose placements for every card in order that maximize final score. Break score ties by lexicographically smaller placement coordinate list `[[row, col], ...]`, comparing rows before columns. For the initial standalone solve of `/app/data`, write `/app/answer.json` with exactly `{"queries":[...]}` in input order. Each query entry must contain `id`, `score`, `charge`, `signature`, `links`, `pulses`, and `placements`, where `placements` is an array of `{"card": card_id, "row": row, "col": col}`.

For that same standalone `/app/data` solve only, also write `/app/profile.json` as an audit of the recovered engine. It must be exactly `{"glyphs":[...],"terrains":[...],"pair_bonus":[...],"anchor_bonus": anchor_bonus,"calibration_audit":{...}}`. `glyphs` is ordered `A`, `B`, `C`, `D`, with entries `{"glyph": g, "weight": weight, "drift": drift}`. `terrains` is ordered `.`, `~`, `^`, `*`, with entries `{"terrain": t, "bias": bias, "drift": drift}`. `pair_bonus` is the 16-row ordered table by previous glyph outer order and current glyph inner order, both `A`, `B`, `C`, `D`; each row is `{"previous": prev, "current": cur, "bonus": value}`. `anchor_bonus` is the recovered integer constant.

The `calibration_audit` object must contain integer fields `single_rows`, `pair_rows`, `max_score_residual`, `charge_mismatches`, and `signature_mismatches`. Re-simulate every calibration row with the recovered profile and that row's script. `single_rows` counts rows whose script contains exactly one move. `pair_rows` counts rows whose script contains exactly two moves and whose second move is orthogonally adjacent to the first, producing exactly one link. `max_score_residual` is the largest absolute difference between simulated and recorded final score. The mismatch fields count rows whose simulated final charge or signature differs from `result`. A correct profile has zero residuals and mismatches on the shipped data.

Also create `/app/solver.py`, runnable as `python3 /app/solver.py INPUT_DIR OUTPUT_JSON`. It must infer the profile from the calibration JSONL inside the given input directory, solve the puzzle JSON inside that directory, and write the answer JSON schema only to `OUTPUT_JSON`. When invoked with those two arguments, do not write `/app/answer.json`, `/app/profile.json`, or any other `/app/*` path. `/app/answer.json` and `/app/profile.json` are produced only by the initial standalone solve of `/app/data`.
