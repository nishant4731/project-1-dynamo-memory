Build `/app/rescue_mix.py`, then run it on `/app/session`. The script must accept one argument, a session directory, and repair that directory in place. After `python3 /app/rescue_mix.py /app/session`, the directory must contain `/app/session/recovered/mix.pcm` and `/app/session/recovered/session_report.json`.

The session has `manifest.json`, `clock_anchors.json`, the `/app/session/calibration/` directory, `ledger/*.ndjson`, and packet bytes under `packets/`. Treat `/app/session/calibration/` as the surviving format evidence for this specific session. Its JSON examples and notes determine the session's codec profile, ledger parity profile, and stream-clock middle rule; hidden sessions use the same families but may have different recovered profile values.

`mix.pcm` is raw signed 16-bit little-endian mono PCM with exactly `manifest["length_samples"]` samples and no WAV header. The report is UTF-8 JSON with sorted keys and no extra top-level keys.

Use only ledger rows that are valid JSON objects with these typed fields: `id`, `track`, `stream`, `packet_path`, `codec`, `start`, `logged_at`, `gain_milli`, `invert`, `sha256`, and `parity`. `track` must be listed in the manifest and `stream` must have a recovered clock offset. `packet_path` is relative to `packets/`; reject absolute paths and paths containing `..`. Reject rows with a missing packet file, a SHA-256 mismatch, an unknown codec, a parity mismatch, or packet bytes that cannot be decoded by their codec.

The `/app/session/calibration/FORMAT_NOTES.txt` file gives the recoverable format families. Derive the exact per-session choices from the calibration JSON:
- `pcm16` is signed 16-bit little-endian samples.
- `dpcm8` stores the first signed 16-bit little-endian sample followed by signed 8-bit deltas with one fixed positive integer step size; examples pin the step size. Clip to signed 16-bit after each delta step.
- `xor16` is `pcm16` after XORing every byte with one of the two bytes of `blake2s((id + "|" + stream).encode(), digest_size=2).digest()`; examples pin the byte index.
- ledger `parity` is the XOR of the first 16 bits of SHA-256, packet byte length, ledger `start`, ledger `gain_milli`, and one session salt; examples pin the salt.
- each stream offset is one of the two middle values from sorted verified `source_sample - logged_sample` differences; examples pin whether this session uses the lower or upper middle.

A packet's effective start is `start + offset`. For every valid decoded packet, negate samples first if `invert` is true, then apply `gain_milli` with integer division toward zero by 1000, then clip to signed 16-bit. If several valid records have the same `(track, effective_start, decoded_length)`, keep the one with the highest `logged_at`; if still tied, keep the lexicographically largest `id`. Drop the others as duplicates.

Assemble each track as signed 16-bit samples initialized to zero. First sort the kept packets by `(track, effective_start, id)`. Process kept packets in that sorted order; for each packet sample, add it to the destination sample and immediately apply signed-16-bit saturation. Do not sum all overlapping packets first and saturate once at the end. Samples landing before 0 or at/after `length_samples` are skipped and counted as clipped-to-bounds. The final mix is the signed-16-bit saturating sum of all tracks in manifest track order, again saturating immediately after each track contribution at each sample.

`session_report.json` must contain exactly: `session_id`, `tracks`, `sample_rate`, `length_samples`, `records_total`, `records_usable`, `records_rejected`, `duplicates_dropped`, `packets_kept`, `samples_clipped_to_bounds`, `mix_peak_abs`, `mix_sha256`, `track_sha256`, and `chosen_packet_ids`. `records_usable` is the count of valid ledger records before duplicate dropping. `records_rejected` has keys `bad_json`, `schema`, `missing_file`, `sha_mismatch`, and `parity_mismatch`: invalid JSON increments `bad_json`; missing typed fields, wrong JSON types, unknown tracks/streams/codecs, absolute or `..` packet paths, and codec decode failures increment `schema`; safe relative paths whose files are absent increment `missing_file`; digest failures increment `sha_mismatch`; parity failures increment `parity_mismatch`. `track_sha256` maps each track name to the SHA-256 of that repaired track's raw PCM bytes. `chosen_packet_ids` is a JSON array of packet id strings only, sorted by each kept packet's `(track, effective_start, id)`; do not output sort-key tuples, objects, or nested arrays.

When both outputs have been written successfully, remove the session's `ledger/` and `packets/` directories. Do not delete `manifest.json`, `clock_anchors.json`, `/app/session/calibration/`, or `recovered/`.
