Vault filtering contract

Inputs are `policy.json`, `records.ndjson`, `score_calibration.tsv`, and payloads under `files/`. Canonical JSON object bytes mean UTF-8 JSON with object keys sorted lexicographically at every object level and compact separators, with no spaces after commas or colons. Standalone JSON artifacts are canonical JSON object bytes plus exactly one trailing newline; JSONL rows are one canonical JSON object followed by `\n`. `record_crc` equals the first 10 hex chars of SHA-256 over the same JSON object without `record_crc`, serialized as canonical JSON object bytes. Bad CRC rows increment only `records_invalid_crc`.

CRC-good rows need a safe payload path: POSIX relative under `files/`, existing regular file, no absolute path, empty part, `.`, `..`, symlink component, missing file, or resolved escape. Size/SHA-256 mismatch is `records_hash_rejected`; path failure is `records_path_rejected`. `records_valid` counts rows passing CRC/path/size/hash, including markers; marker-valid counters are subcounts and markers are never copied. Asset rows keep largest integer `rev` per `asset_id`, tie-broken by larger `record_id`; other valid asset rows are `valid_superseded`.

Normalize tags by strip/lowercase/deduplicate. Normalize regions by strip/lowercase; use that value if in `region_order`, else `region_aliases[normalized]`. Consider only active assets with resolved region, allowed `name_hint` extension, required tags, no blocked tags, and `captured_epoch` in the inclusive retention window ending at `cutoff_epoch`. Lower bound is `cutoff_epoch - keep_days * 86400`, using `legal_hold_keep_days` for `legal_hold`, otherwise `keep_days_by_region[region]`.

A stale non-`legal_hold` asset may use one renewal marker: active, same target/region, renewal-required tags, no blocked tags, positive `renewal_days`, marker timestamp from asset through cutoff. Clamp to `renewal_max_extra_days`; choose greatest clamped days, then latest marker timestamp, then largest marker `record_id`. Used renewal gives reason `renewed_window`, renewal-used counters, and score bonus from the inferred score profile.

Infer the vault-specific score profile from `score_calibration.tsv`; verifier vaults may use different profile values. The TSV header is `case_id	priority	tag_bonus	region_rank	age_days	legal_hold	large_file	renewal_days	review_points	score`. Probe rows are synthetic examples, not vault records. For every probe, `score = priority + tag_bonus + region_rank*region_step + max(0, freshness_cap-age_days) + legal_hold*legal_hold_bonus + large_file*large_file_bonus + renewal + review_points`, where `renewal` is `0` when `renewal_days` is zero, otherwise `renewal_score_bonus + floor(renewal_days / renewal_score_step_days)`. Find the single integer profile matching all probes with `region_step` in `[3,15]`, `freshness_cap` in `[18,45]`, `legal_hold_bonus` in `[8,40]`, `large_file_bonus` in `[1,15]`, `renewal_score_bonus` in `[5,25]`, and `renewal_score_step_days` in `[5, renewal_max_extra_days]`. Asset score uses that profile with `region_rank = len(region_order)-region_index`, `age_days = floor((cutoff_epoch-captured_epoch)/86400)`, `tag_bonus = sum(tag_weight for normalized tags in tag_weight)`, `legal_hold = 1` iff the asset has tag `legal_hold`, `large_file = 1` iff bytes are at least `large_file_bytes`, plus any review points.

Review precedes suppression. Usable review markers are active, same target/region, review-required tags, no blocked tags, non-empty stripped lowercase `reviewer_id`, `decision` `approve`/`reject`, timestamp from asset through cutoff. Per asset/reviewer keep latest timestamp, then largest marker `record_id`. Any kept reject removes a non-`legal_hold` asset (`review_rejected_assets`, `assets_rejected`); legal hold overrides. Kept approvals add capped points per asset, not globally: first clamp each marker's `review_points` to `[0, review_max_points_per_marker]`, then sort approvals by descending clamped points, descending marker timestamp, ascending reviewer id. Walk that sorted list while the asset has fewer than `review_max_points_total` review points; each approval contributes `min(clamped_points, remaining_total)` points, so the final counted marker may contribute only part of its clamped value, and later markers contribute zero. Positive contributing approvals on copied assets feed `review_records_used`, `review_points_total`, score, and reason `review_boosted`; `review_records_used` counts approval markers that contribute a positive amount.

Payload proof precedes review scoring. Usable proof markers are active, same target/region, proof-required tags, no blocked tags, timestamp from asset through cutoff, non-negative integer `proof_offset`, positive integer `proof_length`, positive `proof_points`, and `proof_sha256` equal to SHA-256 of exactly the target asset payload byte window `[proof_offset, proof_offset + proof_length)`. Windows past the target payload end are unusable. Clamp each marker's `proof_points` to `[0, proof_max_points]`; per asset choose greatest clamped points, then latest marker timestamp, then largest marker `record_id`. A used proof adds its clamped points to score and reason `payload_proved`. Used proofs on copied assets feed `proof_records_used` and `proof_points_total`; `proof_records_used` counts selected proof markers, not bytes.

Then apply suppression markers: active, same target/region, suppression-required tags, no blocked tags, timestamp from asset through cutoff. Suppression removes the asset unless it is `legal_hold` and marker lacks tag `override`; count removed copy-candidates in `suppressed_assets` and `assets_rejected`.

Before naming, strip/lowercase `bundle_id`; empty/absent is unbundled. For each non-empty `(region,bundle_id)`, keep at most `bundle_keep_by_region[region]` assets ordered by descending score, descending captured epoch, ascending `asset_id`; dropped assets are `bundle_pruned` and rejected.

For destination names, take the last slash/backslash component of `name_hint`, trim it, split extension at the last dot except a leading-dot-only name has none, and lowercase extension. In the stem, collapse whitespace to `_`, replace characters outside `[A-Za-z0-9._-]` with `_`, strip leading/trailing `._-`, lowercase, and use `unnamed` if empty. Destination is `files/<region>/<stem>[.<ext>]`. Collision groups sort by descending score, descending captured epoch, ascending `asset_id`; first keeps the name, later files append `__02`, `__03`, etc. before the extension.

Copy payloads. Write `manifest.jsonl` sorted by `dest_path`, then `asset_id`; each row is canonical JSON with exactly these fields: `asset_id`, `record_id`, `source_path`, `dest_path`, `sha256`, `bytes`, `score`, `reason_codes`. Manifest paths start with `files/`. Reason code order: window code (`legal_hold_window`, `renewed_window`, or `standard_window`), `region_alias` if used, bundle code (`bundle_member` or `unbundled`), `large_file` if true, `payload_proved` if true, `review_boosted` if true, then name code (`collision_renamed` or `canonical_name`).

Write `audit.tsv` with trailing newline and header `asset_id	record_id	status	region	bundle_id	score	dest_path	reason_codes`. Add one row per revision-winning asset sorted by `asset_id`, then `record_id`. `status` is `policy_rejected`, `window_rejected`, `review_rejected`, `suppressed`, `bundle_pruned`, or `copied`. Use normalized region or `-`, normalized bundle id or `-`, score only for copied/bundle-pruned rows and `0` otherwise, copied destination or `-`, and `|`-joined reason codes; non-copied rows use only status.

Write `report.json` as canonical JSON with exactly these top-level fields: `records_seen`, `records_invalid_crc`, `records_path_rejected`, `records_hash_rejected`, `records_valid`, `renewal_records_valid`, `suppression_records_valid`, `review_records_valid`, `proof_records_valid`, `valid_superseded`, `assets_considered`, `assets_rejected`, `selected_count`, `copied_bytes`, `collision_renames`, `bundle_pruned`, `renewal_records_used`, `renewal_days_total`, `suppressed_assets`, `review_records_used`, `review_points_total`, `review_rejected_assets`, `proof_records_used`, `proof_points_total`, `region_counts`, `extension_counts`, `bundle_counts`, `score_checksum`, `audit_rows`, `audit_sha256`. `assets_considered` is after revision selection and before policy filters; `assets_rejected` equals considered minus copied. Include all policy regions/extensions with zeroes. `bundle_counts` maps retained non-empty bundle ids to copied counts. `score_checksum` is sum over sorted manifest rows of `(1-based row index)*score`. `audit_rows` excludes header; `audit_sha256` is SHA-256 of exact audit TSV bytes.

Write `receipt.json` as canonical JSON. It has top-level keys `audit_status_counts`, `outputs`, `reason_code_counts`, `schema`, and `source`; `schema` equals `vault-filter-receipt-v1`. `source` has exactly `calibration_sha256`, `input_file_bytes`, `input_file_count`, `policy_sha256`, and `records_sha256`, using SHA-256 digests for `score_calibration.tsv`, regular input payload byte/count totals under `files/`, `policy.json`, and `records.ndjson`. Status and reason-count maps omit zeroes and sort naturally by JSON key. `outputs` has exactly `audit_sha256`, `copied_tree_sha256`, `manifest_sha256`, and `report_sha256`: SHA-256 digests for exact `audit.tsv`, copied-payload tree, `manifest.jsonl`, and `report.json` bytes. `copied_tree_sha256` is SHA-256 of the UTF-8 compact canonical JSON array, not JSONL, produced from a list sorted by `path`; each element is an object with exactly `bytes`, `path`, and `sha256`, where `path` is relative to the copied `files/` root and never starts with `files/`.
