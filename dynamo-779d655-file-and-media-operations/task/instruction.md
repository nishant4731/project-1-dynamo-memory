Recover the frozen contact sheet for the design export in `/app/design_export`.

The export contains `/app/design_export/freeze.json`, an unordered `/app/design_export/events.ndjson`, Netpbm tiles under `/app/design_export/tiles`, and row-parity repair bundles under `/app/design_export/repair`. Color tiles are PPM files; alpha tiles are PGM files; input tiles may be text `P3`/`P2` or binary `P6`/`P5` with max value `255` and Netpbm comments either as whole `#` header lines or as trailing `# …` fragments after header tokens on the same line.

Create exactly these outputs:

- `/app/recovered/contact_sheet.ppm`
- `/app/recovered/report.json`
- `/app/recovered/recover_design.py`

`/app/recovered/recover_design.py` must be a reusable Python 3 solver for exports with the same file schemas and rules, not a hardcoded writer for this one export. It must run as `python3 /app/recovered/recover_design.py <design_export_dir> <output_dir>` and write `contact_sheet.ppm` and `report.json` into `<output_dir>`.

The frozen state is defined at `freeze_at` from `/app/design_export/freeze.json`. Ignore any event whose `published_at` is after that instant, even if its `effective_at` or `revision` looks newer. Exact duplicate event records are replay noise and count once. For each `layer_id`, choose the remaining event with the greatest `(effective_at, revision, event_id)` tuple. If the chosen event has `status` `deleted`, that layer is absent.

Render each artboard listed in `/app/design_export/freeze.json` in that order. Start with its `background_rgb`. Draw active layers for that artboard sorted by `(z_index, layer_id)` ascending. For each layer, apply its `transform` to both color and alpha tiles before placement. Supported transforms are `identity`, `rotate90cw`, `rotate180`, and `flip_x_then_rotate90cw`. In `flip_x_then_rotate90cw`, `flip_x` means mirror horizontally by reversing each row, then rotate the mirrored tile 90 degrees clockwise. After the transform, the event's top-level integer `x` and `y` fields are the placement origin: transformed tile coordinate `(tx, ty)` targets artboard coordinate `(x + tx, y + ty)`. A non-null `clip` is `[x, y, width, height]` in artboard coordinates. A layer pixel contributes only when its transformed target coordinate is inside the artboard and inside its clip rectangle when `clip` is not null. Compute effective alpha as `(mask_alpha * opacity + 127) // 255`, then composite each channel as `(src * effective_alpha + dst * (255 - effective_alpha) + 127) // 255`.

When a layer references a `.rpx.json` repair bundle, reconstruct it before applying transforms. A repair bundle has `format` `row_xor_weighted_tile_v2`, integer `width`, `height`, `channels`, `max_value` `255`, array `missing_y`, `row_xor_hex`, `weighted_sum_mod257`, optional `weighted_square_mod257`, and `stored_rows`. Each stored row is raw bytes for row `y`, encoded as hex. `row_xor_hex` is the bytewise XOR of every final row. For each byte position, `weighted_sum_mod257[i]` equals `sum((y + 1) * row_y[i]) mod 257`; when present, `weighted_square_mod257[i]` equals `sum((y + 1) ** 2 * row_y[i]) mod 257` and applies to all missing-row counts, including two-row bundles. There are two, three, or four missing rows, and they may be adjacent. Four-row bundles may appear with or without square residues and may have enough byte positions that full Cartesian enumeration of every byte tuple is not expected to finish within the reusable-solver checks. `missing_y` is not guaranteed to be sorted. The equations can leave more than one byte tuple per position; choose the full missing rows with the smallest seam energy across all missing rows together. Seam energy is a global sum over edges: horizontal adjacent-pixel edges within each missing row, plus each vertical edge between a missing row and an adjacent row, stored or missing, counted exactly once. Each edge cost is the sum over channels of squared byte differences `(a - b) ** 2`; alpha tiles have one channel and RGB tiles have three. There is no hidden original-row preference beyond these fields: the parity equations plus the seam-energy and lexicographic rules are the canonical decoding rule. If energies tie, choose the lexicographically smallest concatenation of missing rows in `missing_y` order. Then interpret rows by increasing `y`; `channels` is `3` for RGB color and `1` for alpha.

Build `/app/recovered/contact_sheet.ppm` as a `P3` PPM with max value `255`. All artboards have the same size. Place them into the sheet using `columns`, `gutter`, and `gutter_rgb` from `/app/design_export/freeze.json`; gutter pixels appear only between neighboring artboards and are exactly `gutter_rgb`. There is no outer border around the sheet, so a full row has width `columns * artboard_width + (columns - 1) * gutter`.

`/app/recovered/report.json` must be valid JSON with this top-level schema:

`freeze_at`: the freeze timestamp string.
`sheet`: object with integer `width`, integer `height`, and `pixel_sha256`.
`ignored_events`: object with integer `duplicate_replays`, integer `published_after_freeze`, and sorted string array `deleted_layers`.
`repaired_tiles`: array sorted by `path`; each entry has `path`, `missing_y`, integer `channels`, and `byte_sha256` over every row of the fully reconstructed tile, in increasing `y` order. Report each entry's `missing_y` exactly as it appears in that repair bundle, preserving the original order rather than sorting it.
`artboards`: array in freeze-file order. Each entry has `id`, `size` as `[width, height]`, `visible_layers` in draw order for layers whose compositing changed at least one RGB pixel, `pixel_sha256`, integer `non_background_pixels`, and `palette_top`.

All `pixel_sha256` values are SHA-256 over raw row-major RGB bytes, not over PPM or JSON text. `non_background_pixels` counts pixels different from that artboard's background color after rendering. `palette_top` contains the six most common final RGB colors as objects `{"rgb": [r, g, b], "count": n}`, sorted by descending count and then ascending RGB tuple.
