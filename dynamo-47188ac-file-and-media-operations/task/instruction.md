Write `/app/recover_camera.py`, a Python program that repairs a crashed tiled grayscale video drop. It will be run as `python3 /app/recover_camera.py INPUT_DIR OUTPUT_DIR`.

`INPUT_DIR` contains `manifest.json`, `sync.tsv`, and `fragments/*.vfrag`. The manifest gives `width`, `height`, `fps`, `frame_count`, and `tiles`, where each tile is `[x, y, w, h]`. The output directory must contain:

`clip.y4m`: a YUV4MPEG2 grayscale stream. The header must be exactly `YUV4MPEG2 W{width} H{height} F{fps}:1 Ip A1:1 Cmono\n`. For each global frame from `0` through `frame_count - 1`, append `FRAME\n` followed by `width * height` bytes, row-major. Manifest tiles may overlap. Compose each frame by painting selected tiles in manifest list order so a later tile overwrites earlier pixels in any shared region; pixels never painted by any selected tile remain zero.

`repair_report.json`: a JSON object with integer keys `frames_written`, `tiles_written`, `missing_tiles`, `frames_with_repairs`, `discarded_bad_payload_hash`, `discarded_bad_frame_crc`, `discarded_status`, `discarded_unsynced_epoch`, `discarded_out_of_range`, `shadowed_fragments`, `decoded_xor_frames`, `decoded_rle_frames`, `corrected_tiles`, and `clipped_pixels`. Key order and whitespace do not matter. `frames_written` equals `frame_count`.

The program must consume evidence: after each `.vfrag` file is classified (whether kept or discarded), delete that file from `INPUT_DIR/fragments`. Do not delete `manifest.json` or `sync.tsv`.

`sync.tsv` has columns `camera`, `epoch`, `local_frame`, `global_frame`, `state`, and `quality`. Treat `epoch` as an opaque string. For each `(camera, epoch)` pair, use only rows with `state` equal to `locked` whose `quality` field matches `^(0|[1-9][0-9]*)$` and has integer value `>= 900`. Ignore every other row, including values such as `900.0`, `+900`, or `0900`. The pair's offset is `local_frame - global_frame`. Use the most frequent qualifying offset for that pair; ties choose the smaller offset. A fragment whose `(camera, epoch)` pair has no qualifying row is unsynced.

Each `.vfrag` file is one JSON object with `fragment_id`, `camera`, `epoch`, `local_start`, `revision`, `phase`, `status`, `tile`, `packing`, `frames`, `payload_sha256`, `frame_crc32`, `gain_q8`, and `bias`. Decode each tile frame to exactly `w * h` bytes for the fragment tile. For `packing` `raw`, each frame string is raw lowercase hex bytes. For `xor_delta`, frame 0 is raw bytes and each later string is bytes to XOR with the previous decoded frame. For `rle`, each frame string is hex pairs of unsigned bytes `(count, value)`, expanded in order; counts are positive and the expansion must be exactly the tile byte count. `payload_sha256` is SHA-256 of the binary bytes obtained by hex-decoding each string in `frames` and concatenating those bytes in order, before raw/xor/RLE frame decoding. `frame_crc32` lists 8-digit lowercase hexadecimal CRC-32 values of the decoded tile frames before gain/bias correction.

Classify fragments in this order. If the encoded payload hash does not match `payload_sha256`, discard it and count `discarded_bad_payload_hash`. Else if any decoded frame's CRC-32 does not match its listed value, discard it and count `discarded_bad_frame_crc`. Else if `status` is not `committed`, discard it and count `discarded_status`. Else if the `(camera, epoch)` pair is unsynced, discard it and count `discarded_unsynced_epoch`.

A fragment that survives those four checks is non-discarded. `decoded_xor_frames` and `decoded_rle_frames` count decoded frames from non-discarded fragments using those packings. If a non-discarded fragment's tile is not exactly one manifest tile rectangle, do not place any of its frames and do not count it as out-of-range or shadowed. Otherwise, for every decoded fragment frame at index `i`, its global frame is `local_start - offset + i`. If that global frame is outside `[0, frame_count)`, count one `discarded_out_of_range` tile candidate and do not place it. Remaining frames are in-range candidates for that frame and tile.

When several candidates target the same frame and tile rectangle, newer revisions win. Among equal revisions, later lifecycle stages win as the lifecycle progresses `preview` → `patch` → `final`. Among those, choose the lexicographically smallest `fragment_id`. Before rendering a selected tile, form the exact rational `byte * gain_q8 / 256 + bias`, round that single value to the nearest integer with ties to even, then clamp to `[0, 255]`. Floating-point evaluation is not authoritative. `corrected_tiles` counts selected frame-tile placements whose corrected bytes differ from the pre-correction bytes. `clipped_pixels` counts corrected selected pixels clamped to `0` or `255`. `tiles_written` is selected placements. `missing_tiles` is manifest frame-tile slots without a selected placement. `frames_with_repairs` is frames with at least one missing tile. `shadowed_fragments` counts fragments that contributed at least one in-range candidate but won zero selected placements.
