Recover the approved press proof from `/app/data/proof_package` and write `/app/proof_out/final.ppm`, `/app/proof_out/proof_report.json`, and `/app/proof_out/recover_proof.py`. The Python program must read `PROOF_PACKAGE_DIR` and `OUTPUT_DIR`, defaulting to `/app/data/proof_package` and `/app/proof_out`, and perform the same recovery for any package with this format.

The package manifest is `/app/data/proof_package/manifest.json`; its approval ledger path is relative to the package directory. Use `cutoff_utc`. Ledger rows later than the cutoff do not exist, but rows whose `timestamp_utc` is exactly equal to `cutoff_utc` are included. Process remaining rows by ascending `timestamp_utc`, preserving file order for equal timestamps. `approve` sets that exact `(proof_id, revision)` approved, and a later `withdraw` sets it withdrawn. For each `proof_id`, the active proof is the highest revision whose final state at the cutoff is approved. Layers whose proof has no active revision are skipped.

Every manifest fragment is a payload-only indexed-image rectangle. Validate each fragment against `payload_sha256`. For an `xor_payload_bytes` repair group, if exactly one member is missing or has a bad hash, recover that member by XORing the parity payload with the other member payloads byte by byte; the parity payload itself must match its manifest hash. Decoded fragment rectangles are applied to an initially transparent proof image in ascending `sequence`; later fragments overwrite earlier pixels, and out-of-bounds fragment pixels are clipped.

Codecs decode to palette-index rows of `width * height` pixels. `idxraw` is raw row-major bytes. `idxrle` stores `(count, palette_index)` byte pairs, expanded in order. `bitpack` stores fixed-width indexes using `bits_per_index`, most significant bits first, ignoring final padding bits. `rowxor` stores the first row raw, then each later byte is XORed with the decoded byte directly above it.

Render manifest `layers` in file order onto an RGB canvas initialized to `canvas.background_rgb`. Palette entries are `[red, green, blue, alpha]`; palette alpha 0 pixels do not draw. For each in-bounds source pixel, compute `alpha = floor(palette_alpha * opacity_num / opacity_den)` and source-over blend each RGB channel as `floor((src * alpha + dst * (255 - alpha) + 127) / 255)`. In `overprint` mode only, a source RGB channel whose value is 0 leaves that destination channel unchanged instead of blending. Coordinates are zero-based; negative layer offsets clip normally.

Before rendering, solve manifest `registration`. Choose exactly one `[dx, dy]` offset candidate from each item in item order so that the sum of `residue_weight * ((dx + 1009) * 131 + (dy + 1009) * 137 + item_index + 1)` is congruent to `target_residue` modulo `residue_mod`, where `item_index` is zero-based. Among valid choices, minimize `sum(drift_weight * (abs(dx) + abs(dy)))`; ties use the lexicographically smallest offset vector in item order, and that tie-break is part of the required output contract. The visible package includes such a tie in its final two registration items: both equal-cost choices reach the target, so the selected report must use the lexicographically earlier item-order vector. Add selected offsets cumulatively to their named layer's base `x` and `y` before rendering. Hidden verifier packages include small-modulus many-candidate cases with `residue_mod` `9973` and `18` items, plus a large-modulus binary-choice case with `residue_mod` `1000000007` and `36` items; do not enumerate every combination or allocate arrays proportional to `residue_mod`.

`/app/proof_out/final.ppm` must be ASCII P3: header `P3`, then `width height`, then `255`, then one row of space-separated RGB integers per canvas row. `/app/proof_out/proof_report.json` must be minified JSON with sorted keys and exactly `cutoff_utc`, `canvas`, `active_proofs`, `registration`, `layers`, and `ppm_rgb_sha256`. `canvas` has `width` and `height`. `active_proofs` is sorted by `proof_id`; each entry has `proof_id`, `revision`, and `pixel_sha256`, the SHA-256 of the active proof's palette-index bytes after fragment repair. `registration` has `residue_mod`, `target_residue`, `cost`, and `selected_offsets`; selected offsets are item-order objects with `layer_id`, `dx`, and `dy`. `layers` lists drawn layers in render order after registration; each entry has `layer_id`, `proof_id`, `revision`, `x`, `y`, `mode`, and `drawn_pixels`, counting nontransparent source pixels that land in bounds. `ppm_rgb_sha256` is the SHA-256 of the final canvas RGB bytes in row-major order, not the PPM text.

All three outputs must be regular files.
