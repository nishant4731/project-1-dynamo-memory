Recover the final design-review atlas described by `/app/data/manifest.json`. Write the PNG atlas to `/app/recovered_atlas.png`, the audit report to `/app/recovery_report.json`, and a reusable solver script to `/app/recover_atlas.py`.

`/app/recover_atlas.py` must be executable with `python3 /app/recover_atlas.py --data-dir <input-dir> --atlas <png-path> --report <json-path>`. It must apply the same rules below to any input directory with the same file schema as `/app/data`. After creating the script, use it to produce `/app/recovered_atlas.png` and `/app/recovery_report.json` from `/app/data`.

Input records use UTC ISO timestamps. For each frame in `/app/data/manifest.json`, build the artwork state independently. A placement event is eligible only when `published_at <= published_cutoff` and `effective_from <= as_of` for that frame. For each `slot`, choose the eligible event with the greatest `(effective_from, revision, published_at, id)` tuple. If the chosen event has `"action": "remove"`, that slot contributes nothing.

Sprites live in `/app/data/sprites`. Each sprite file starts with `SPRITE <name> <width> <height>`, then `PIXELS`, then exactly `height` pixel rows. A row is either exactly `width` raw symbols or a run-length row beginning with `@`; after `@`, each term is one non-digit symbol followed by its decimal repeat count, and the expanded row must have width `width`. `.` is transparent; all other symbols are defined in `/app/data/palette.csv`.

If `palette_events.jsonl` exists in the data directory, apply it independently for each frame before `palette_overrides`. A palette event is eligible by the same `published_at <= published_cutoff` and `effective_from <= as_of` rule; for each `symbol`, choose the greatest `(effective_from, revision, published_at, id)` tuple. An event with `"action": "set"` changes that symbol to its `hex` color for the frame. An event with `"action": "remove"` restores the base `/app/data/palette.csv` color for that symbol.

Before rendering, solve the proof lock in `/app/data/variant_locks.json`. For a scalar lock, select exactly `select_count` candidates whose `weight` values sum to `target` modulo `modulus`. For a multidimensional lock, `targets` maps dimension names to target residues and each candidate has a `weights` object; the selected set must hit every dimension's target modulo `modulus`, using 0 for any missing candidate dimension. If `forbidden_pairs` is present, no selected set may contain both candidate names in any listed pair. If more than one candidate set is valid, use the one whose sorted list of candidate `name` values is lexicographically smallest; the order of candidates in the JSON file is not authoritative. Chosen candidates are extra sprite placements; draw each chosen candidate only on frames whose `name` is listed in its `frames` array.

For a placed sprite, rotate clockwise by `rotation` degrees first, then apply `flip_x` by mirroring the rotated rows. Draw non-transparent sprite pixels at `(x + column, y + row)` and ignore pixels outside the canvas. If the placement has `clip_rect`, draw only pixels whose canvas coordinate is inside `[left, top, right, bottom)` from that four-number array. Composite placements by increasing `z`; ties use the slot name for base placements and the candidate `name` for proof-lock overlays, alphabetically. The canvas starts filled with the manifest background color. If a frame has `palette_overrides`, those `symbol -> #rrggbb` colors replace `/app/data/palette.csv` colors for that frame only.

Blend a source RGB channel `s` over destination channel `d` as follows: `normal = s`, `multiply = (s*d + 127)//255`, `screen = 255 - (((255-s)*(255-d) + 127)//255)`, `difference = abs(s-d)`, and `lighten = max(s,d)`. Then apply integer alpha percentage `a` with `(a*blend + (100-a)*d + 50)//100`. If a placement has `alpha_by_symbol`, use `alpha_by_symbol[symbol]` as `a` for that source pixel when present; otherwise use the placement's `alpha`. Base placement events and chosen proof-lock candidates share the same transform and blending fields. The output atlas places frames left to right in manifest order with no gap.

If `frame_effects.jsonl` exists, apply it after all placements for each frame but before report hashes and atlas assembly. Frame-effect events use the same eligibility rule; for each `effect` name, choose the greatest `(effective_from, revision, published_at, id)` tuple. A chosen `"action": "remove"` disables that effect. Apply remaining effects by increasing `(order, effect)`. Each effect may have `frames`; omit the effect unless the frame name or `"*"` is listed. `rect`, when present, is `[left, top, right, bottom)`; otherwise use the whole frame. `replace_color` changes exact `from` RGB to `to`. `channel_shift` adds signed `dr`, `dg`, and `db` to RGB channels, clamped to `0..255`. `tint_rect` blends its `hex` color over every pixel in the rect with its integer `alpha` using the normal blend formula above.

`/app/recovery_report.json` must be a JSON object with exactly these top-level keys: `atlas_sha256`, `selected_overlays`, `frames`, and `global_palette`. `atlas_sha256` is the lowercase SHA-256 hex digest of the bytes in `/app/recovered_atlas.png`. `selected_overlays` is the sorted chosen proof-lock candidate-name list. `frames` is a list in manifest order; each item has exactly `name`, `rgb_sha256`, `active_slots`, `non_background_pixels`, and `distinct_colors`. `rgb_sha256` is the lowercase SHA-256 of that frame's raw row-major RGB bytes. `active_slots` is the sorted list of placed slot names plus chosen overlay names drawn on that frame. `non_background_pixels` counts pixels whose RGB differs from the manifest background. `distinct_colors` counts unique RGB colors in that frame. `global_palette` maps lowercase `#rrggbb` colors to their pixel counts across the whole atlas.
