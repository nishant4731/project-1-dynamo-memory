Recover the crashed RVF grayscale capture in `/app/session`.

Create an executable Python file at `/app/recover_spool.py`. The command line is exactly `SESSION_DIR OUTPUT_DIR`; execute it once as `/app/recover_spool.py /app/session /app/output`. A successful run emits `/app/output/recovered.rvf`, `/app/output/contact_sheet.pgm`, `/app/output/frame_stats.csv`, `/app/output/recovery_report.json`, `/app/output/recovery_audit.tsv`, and `/app/output/output_index.tsv`. It then deletes only `/app/session/calibration.tsv`, `/app/session/records.jsonl`, `/app/session/taps.tsv`, and `/app/session/patches.tsv`; `/app/session/manifest.json` and `/app/session/FORMAT_NOTES.txt` must remain.

`/app/session/manifest.json` contains positive integer `width`, `height`, `frames`, `key_period`, plus string `fps`; echo the `fps` string exactly and do not require ratio syntax. Start with `frames` zeroed images of `width*height` bytes. `/app/session/calibration.tsv` has columns `residue plain_hex encoded_hex`; every residue from `0` through `key_period-1` appears once, and its XOR key byte is `plain ^ encoded`. A payload byte at `(frame,x,y)` uses key residue `(frame*width*height + y*width + x) % key_period`.

Each nonblank line of `/app/session/records.jsonl` is considered alone. A usable record is a JSON object with nonempty string `id`; integer `seq`, `frame`, `x`, `y`, `w`, `h`; `op` of `replace`, `add`, or `under`; string `encoded_hex`; string `decoded_sha256`; boolean `retired`; and `alpha:null` except that `under` requires integer `alpha` in `0..255`. Malformed JSON or schema errors count as `records.bad_schema`. A rectangle outside its frame counts as `records.bad_bounds`. Wrong decoded length or SHA-256 counts as `records.bad_hash`. Valid retired rows count as `records.retired`; all other valid rows count as `records.accepted`.

`/app/session/taps.tsv` columns are `id seq src_frame dst_frame src_x src_y dst_x dst_y w h stride gain_num gain_den bias op source_sha256`. Parse integers strictly; `w`, `h`, `stride`, and `gain_den` are positive; `op` is `replace` or `add`; bad rows count as `taps.bad_schema`. If `src_frame > dst_frame`, count `taps.ignored_future` and skip later checks. Otherwise source and destination rectangles must fit, or count `taps.bad_bounds`. When the tap reaches its render-order position, read its source rectangle with slot `(i*stride) % (w*h)`, verify `source_sha256`, or count `taps.bad_hash`. Transform source byte `value` to `floor(value*gain_num/gain_den)+bias`, clamp to byte range, count clamped bytes in `taps.clipped_pixels`, apply the tap, and count `taps.applied`.

Render records and taps together by sorting `(seq, kind, id)`, where records use kind `0` and taps kind `1`. Record operations are: `replace` assigns, `add` saturates at `255`, and `under` assigns `floor((incoming*alpha + current*(255-alpha))/255)`.

After rendering that stream, apply `/app/session/patches.tsv` in file order. Columns are `id frame x y w h stride op delta_hex before_sha256`; integer and rectangle rules match taps, `op` is `replace`, `add`, or `xor`, `before_sha256` is nonempty, and `delta_hex` must decode to `w*h` bytes. Schema failures count as `patches.bad_schema`, bounds failures as `patches.bad_bounds`, and mismatched current target-rectangle hashes as `patches.bad_hash`. Verify `before_sha256` over the current target rectangle read in slot order `(i*stride) % (w*h)`, using the same coordinate mapping as taps. Applied patch bytes are row-major: `replace` assigns, `add` saturates while counting `patches.saturated_pixels`, and `xor` byte-XORs. Count each applied row as `patches.applied`.

`/app/output/recovered.rvf` is bytes `RVF1 {width} {height} {frames} {fps}\n` followed by final frame bytes in frame order. `/app/output/contact_sheet.pgm` is binary PGM `P5\n{width*frames} {height}\n255\n` followed by rows from each frame laid left to right. `/app/output/frame_stats.csv` has header `frame,min,max,mean_floor,nonzero,bin00,...,bin15`; every frame gets one row, `mean_floor` is floored average pixel value, and bins are 16-value buckets from `0..15` through `240..255`. All text outputs use Unix LF line endings only.

`/app/output/recovery_report.json` is compact JSON, sorted keys, exactly one trailing newline, and exactly these top-level keys: `format`, `width`, `height`, `frames`, `fps`, `records`, `taps`, `patches`, `frame_sha256`, `evidence_removed`. Use JSON integers for dimensions and counters, `format` is `RVF1`, `frame_sha256` lists each final frame digest, and `evidence_removed` is the ordered basename list for the four consumed absolute evidence paths named above. Inside the `records`, `taps`, and `patches` objects, counter keys are the short unprefixed names such as `accepted`, `bad_schema`, `applied`, and `saturated_pixels`; the dotted forms above identify the section plus counter and are not literal JSON keys. `/app/output/recovery_audit.tsv` has header `section name value`; rows are `meta` for `format,width,height,frames,fps`, then `records` counters sorted by counter name, then `taps` counters sorted by counter name, then `patches` counters sorted by counter name, then `frame_sha256` by frame index, then `evidence_removed` by list index, with one trailing newline. Its `name` column also uses the short unprefixed counter name. Keep that section order fixed; only names inside each section group are sorted. `/app/output/output_index.tsv` has header `artifact sha256 bytes`; in order, its artifact column uses only the basenames `recovered.rvf`, `contact_sheet.pgm`, `frame_stats.csv`, `recovery_report.json`, and `recovery_audit.tsv`, and each row lists the exact bytes written for that artifact.
