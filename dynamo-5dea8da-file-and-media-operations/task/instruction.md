Restore the reel from `/app/data/manifest.json`, `/app/data/fragment_log.jsonl`, `/app/data/orientation_schedule.jsonl`, and `/app/data/recall_registry.jsonl`.

Write exactly four outputs:

- `/app/restored/reel.y4m`: YUV4MPEG2. Header exactly `YUV4MPEG2 W16 H12 F5:1 Ip A1:1 Cmono\n`; for each of 14 frames append `FRAME\n` then 192 row-major luma bytes.
- `/app/restored/audit.json`: JSON with exactly: `width`, `height`, `frames`, `fps`, `video_sha256`, `frame_luma_sums`, `bright_pixels`, `repaired_tiles`, `record_counts`, `tile_record_summary`, `selected_codec_counts`, `frame_direct_replacement_counts`, `frame_parity_repair_counts`, `parity_summary`, `orientation_mode_by_frame`, `vetoed_valid_tiles`, and `consumed_fragment_rows`. `video_sha256` is lowercase SHA-256 of `/app/restored/reel.y4m`. Shipped `frame_luma_sums` and `bright_pixels` (luma >= 200) are 14-element lists; CLI workspaces use their manifest frame count. `repaired_tiles` lists `{frame,tile}` for parity-reconstructed tiles, sorted by frame then tile.
- `/app/restored/provenance.json`: JSON with exactly `direct_tiles`, `parity_repairs`, `frame_delta_sha256`, and `fragment_path_sha256`. `direct_tiles` is sorted by frame then tile; each object has `frame`, `tile`, `fragment_id`, `revision`, `codec`, `decoded_sha256`. `parity_repairs` is used parity provenance in processing order; each object has `frame`, `tile`, `fragment_id`, `members`, `chained`, `payload_sha256` (`members` are sensor coords). `frame_delta_sha256` has one SHA-256 per frame over XOR between that restored frame and its starting frame. `fragment_path_sha256` hashes selected direct `fragment_id`s in `direct_tiles` order, then used parity `fragment_id`s in `parity_repairs` order, joined with `\n` plus final `\n`.
- `/app/restored/restore_reel.py`: Python 3 CLI: `python3 /app/restored/restore_reel.py INPUT_DATA_DIR OUTPUT_DIR`. It reads the four inputs from `INPUT_DATA_DIR`, writes `reel.y4m`, `audit.json`, and `provenance.json` into `OUTPUT_DIR`, then deletes `fragment_log.jsonl` from `INPUT_DATA_DIR`. `consumed_fragment_rows` is the JSONL row count before deletion. For CLI workspaces, derive width, height, frames, and fps from their manifest; never hardcode `/app/data`.

Manifest fields are `clip_id`, `width`, `height`, `frames`, `fps`, `tile_size` (`4`), `fragment_log`, and `notes`. Shipped frames are 16x12 in 4x4 tiles (`tiles_per_row` = 4, `tiles_per_col` = 3). Frame 0 starts all-zero; later frames inherit the previous restored frame.

`/app/data/orientation_schedule.jsonl` rows have `effective_from_frame` and `mode` (`forward`, `mirror_x`, or `mirror_y`). For frame `f`, use greatest `effective_from_frame <= f`; ties keep later file-order row. Fragment `tile` values are sensor coords `[sx,sy]`. Display coords: `[sx,sy]` for `forward`, `[tiles_per_row - 1 - sx, sy]` for `mirror_x`, `[sx, tiles_per_col - 1 - sy]` for `mirror_y`. `orientation_mode_by_frame` has one mode per manifest frame.

`/app/data/recall_registry.jsonl` rows have `fragment_id` and `op` (`confirm` or `veto`) in file order. A `fragment_id` is permanently vetoed if any `veto` row names it; later `confirm` does not clear it. `vetoed_valid_tiles` counts active tile records that decode and pass checksum but are vetoed before selection.

Process only `status=active` records. For a `tile`, decode the payload into the final applied 16-byte luma tile; discard unless its SHA-256 equals `decoded_sha256`. Discard vetoed `fragment_id`s next. Selection key is `(frame, display_tile)`: highest `revision` wins; ties use lexicographically smallest `fragment_id`.

Tile codecs:

- `raw`: `payload_b64` decodes to 16 row-major luma bytes.
- `rle`: `payload_b64` decodes to `(count,value)` pairs expanding in order to exactly 16 bytes.
- `delta_prev`: final tile is each `payload_b64` byte plus the same display tile from the previous restored frame, modulo 256; checksum uses that final tile.
- `zigzag`: `payload_b64` decodes to 16 bytes in 4x4 diagonal zigzag from upper left; even diagonals go bottom-to-top and odd diagonals top-to-bottom.

After direct selection for a frame, process active `parity` records for that frame in ascending `fragment_id` order. Map listed `members` sensor coords through the frame orientation before presence tests. A parity payload is bytewise XOR of final replacement tiles for all mapped members; verify `payload_sha256` on decoded parity payload. Use a parity record only when exactly one mapped member lacks a valid replacement; earlier same-frame parity fills count as present. Reconstruct the missing replacement by XOR and apply it at the missing display tile. Ignore the record if zero or multiple mapped members are missing.

Audit rules: `record_counts` has `total`, `by_kind`, and `by_status` over every `fragment_log.jsonl` row. `tile_record_summary` has exactly `decode_errors`, `checksum_rejects`, `valid_records`, `selected_direct_tiles`, and `superseded_valid_tiles`; `valid_records` counts every tile decoded and checksum-passing, including later-vetoed ones; a valid non-vetoed tile is superseded when it lost revision/`fragment_id` selection for its display key. `selected_codec_counts` counts selected direct tiles by `raw`, `rle`, `delta_prev`, `zigzag`. `frame_direct_replacement_counts` is after direct selection before parity. `frame_parity_repair_counts` is after parity before applying the frame. `parity_summary` has `checked`, `checksum_rejects`, `used`, `ignored_no_missing`, `ignored_many_missing`, `chained_repairs`; `chained_repairs` counts used parity records where at least one non-missing mapped member was filled by earlier same-frame parity.
