# Merge conflict contracts

This file is an authoritative shiproom checklist for the recovered 2.7 tree. Use it to
implement the semantic result of overlapping release-material rows; you do not need to
dump every topic branch body once the source commits and patch ids have been recorded.

| Area | Required recovered behavior |
| --- | --- |
| Allocation | Preserve LX-1842 deterministic remainder placement and LX-1926 refund direction: allocate `abs(total_cents)` by weight, place remainders by fractional part then lower index, and restore the original sign to each share. Canonical vectors include `allocate_cents(-101, [5, 3, 2]) == [-51, -30, -20]` and `allocate_cents(-7, [1, 2, 3]) == [-1, -2, -4]`. |
| Settlement | Keep the LX-1855 function shape `entries_for_business_day(entries, day, tz_name="America/New_York")`; compare local dates and exclude LX-1933 reversal rows. Resolve the timezone using the shared history rule below. |
| Settlement buckets | Keep `settlement_period_key(entry, tz_name="America/New_York")`; use `settlement_period_at` when present, otherwise `posted_at`, then return the local date using the shared history rule. The default-zone canonical vectors are `03:30Z on 2025-04-18 -> 2025-04-17`, `04:30Z on the 2025-03-09 DST transition -> 2025-03-08`, and `07:30Z -> 2025-03-09`. |
| Merchant timezone history | For either settlement function, use `merchant_tz_history` when nonempty, otherwise static `merchant_tz`, otherwise `tz_name`. The event cutoff is that function's selected timestamp anchor; the knowledge cutoff is `timezone_knowledge_at`, defaulting to the anchor. Treat equal `timezone_id` rows as revisions: discard future-recorded revisions, then retain the latest `recorded_at` instant with larger numeric `source_seq` as an equal-instant tie-break. Rows without `timezone_id` are independent. From retained facts choose the latest `effective_at` instant not after the event cutoff, with the same numeric tie-break. A retired winner or no winner falls back to static/default timezone. Normalize all timestamp offsets before comparison. |
| Due dates | Apply LX-2024 net terms from the approved waiver row first, then roll Saturday or Sunday due dates forward to Monday; ignore the denied waiver row. |
| Idempotency/config | Use LX-1870v2 SHA256 over compact sorted JSON with keys `currency`, `invoice_id`, sorted `lines`, `merchant_id`, and `retry_generation`; keep `REQUIRE_MERCHANT_ID = True`; do not keep the superseded SHA1 row. |
| Retry | Compute `created_at + 15 * (retry_generation + 1)` minutes, then cap to `deadline_cap` when present. |
| Merchant codes | Keep `merchant_code(raw, as_of=None, aliases=None, merchant_id=None, knowledge_at=None)`. Return `UNKNOWN` for `None`, reject `""`, and preserve other raw codes. Resolve aliases as a graph under the same tenant and time cutoffs at every hop. For the current code, scope rows by raw code and tenant, then treat rows sharing `alias_id` as revisions: discard revisions recorded after `knowledge_at` (default `as_of`), compare `recorded_at` as instants (default `effective_at`), and retain the latest revision with numeric `source_seq` as the equal-instant tie-break; rows without `alias_id` are independent. From retained revisions choose the latest `effective_at` instant not later than `as_of`, again breaking equal instants by numeric `source_seq`. Normalize offsets before every comparison: an alias effective at `2025-05-01T00:30:00-04:00` is ineligible for an event at `2025-05-01T04:15:00+00:00`, so a `2025-05-01T04:00:00+00:00` alias wins; at `04:45Z`, the offset alias wins. Missing sequence is `0`. Follow a winning canonical code as the next graph node. No winning row returns the current code; a winning `state: retired` row also returns the current code and suppresses only that hop. If traversal would revisit any code, return the original input code. Do not apply PX-331 normalization. |
