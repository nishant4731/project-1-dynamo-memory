Recover the canonical rollcall reel from `/app/data/reel_packets.rvp` and `/app/data/cut_plan.csv`; packet fields are defined in `/app/data/FORMAT.md`. Also create `/app/recover_rollcall.py`. Running `python3 /app/recover_rollcall.py <data_dir> <output_dir>` must apply the same rules to any directory containing `reel_packets.rvp` and `cut_plan.csv`, writing `recovered_rollcall.pgm`, `recovered_manifest.json`, and `recovery_audit.json` in `<output_dir>`.

Frames are 48 by 32 grayscale pixels, split into 8 by 8 tiles. Do not assume packet order. If `clock_offsets.csv` exists, add `offset_ms` to `published_ms` for packets whose `seq` is in the inclusive `band_start_seq` to `band_end_seq` range before cutoff comparisons. For each cut-plan row, independently use packets with the same `capture_ms` and adjusted `published_ms <= cutoff_ms`.

For each tile row, choose the highest-revision `PARITY` packet with valid decoded length and CRC-32; break ties by largest `seq`. Its `revision` is authoritative for that row. For each tile column, consider only `TILE` packets at that authoritative revision and choose the largest `seq`. Record selected tile seqs before CRC rejection. Decode selected tiles, require 64 bytes and matching CRC-32, and mark failed or missing tiles unavailable. If exactly one tile in a row is unavailable, recover it by XORing the selected row parity bytes with the other five tiles. If two or more tiles in a row are unavailable, fill each unavailable tile with 64 zero bytes.

Create `/app/recovered_rollcall.pgm` as binary `P5` with header `P5\n<width> <height>\n255\n`, followed by raw bytes. Place frames in cut-plan order, four columns per contact-sheet row, with one-pixel black gaps only between adjacent frames and no outer border: sheet width is `4*48 + 3*1`, sheet height is `rows*32 + (rows-1)*1`, and frame `(col,row)` starts at pixel `(col*(48+1), row*(32+1))` with the first frame at `(0,0)`.

Create `/app/recovered_manifest.json` as compact valid JSON. Top-level keys, in order, are `format`, `frame_size`, `frame_count`, `contact_sheet`, `frames`. Use `format: "rollcall-reel-v1"` and `frame_size: [48, 32]`. `contact_sheet` has `path`, `columns: 4`, `gap: 1`, and `sha256` of the complete PGM; for the `/app` run, `path` is `/app/recovered_rollcall.pgm`, and custom runs use the absolute custom PGM path.

Each frame entry has `index`, `capture_ms`, `cutoff_ms`, `sha256` of the 1536 frame bytes, `repaired_tiles`, `zero_filled_tiles`, `packet_audit`, and `row_decisions`. Sort repaired and zero-filled tile records by row then column. Repaired records are `row`, `col`, `revision`, `method: "row_parity"`. Zero-filled records are `row`, `col`, `revision`, `reason: "unrecoverable_row"`. Empty cases must be empty lists.

`packet_audit` fields are `in_window_packets`, `discarded_late_packets`, `valid_parity_packets`, `invalid_parity_packets`, `selected_tile_packets`, and `crc_bad_selected_tiles`. Count selected tiles after revision/seq selection and before CRC rejection.

Each `row_decisions` entry has `row`, `revision`, `parity_seq`, `valid_parity_candidates`, `ignored_valid_parity_seqs`, `selected_tile_seqs`, `bad_or_missing_cols`, `crc_bad_selected_cols`, and `action`. `valid_parity_candidates` is the integer count of valid in-window `PARITY` packets for that row. Sort ignored parity seqs and bad column lists ascending. `selected_tile_seqs` is a six-item list with seq or null for columns 0 through 5 after revision/seq selection. `action` is `complete`, `row_parity`, or `zero_fill`.

Create `/app/recovery_audit.json` as compact valid JSON. Top-level keys are `format`, `source_dir`, `output_dir`, `frame_count`, `packet_totals`, `decision_totals`, `frame_order_digest`. Use `format: "rollcall-recovery-audit-v1"`; for the `/app` run use `source_dir: "/app/data"` and `output_dir: "/app"`, while custom runs use absolute paths.

`packet_totals` fields are `raw_packet_lines`, `raw_in_window_packets`, `adjusted_in_window_packets`, `discarded_late_packets`, `clock_shifted_in_packets`, `clock_shifted_out_packets`, `valid_parity_packets`, `invalid_parity_packets`, `selected_tile_packets`, and `crc_bad_selected_tiles`. `raw_packet_lines` counts non-comment packet lines. Raw/adjusted in-window counts and shifted-in/out counts are all summed over cut rows for matching captures: if two cut rows share a `capture_ms`, a qualifying packet line contributes once to each of those rows. Shifted-in lines are included only after clock adjustment; shifted-out lines are excluded only after clock adjustment. Do not collapse duplicates by `seq` across rows.

`decision_totals` fields are `complete_rows`, `row_parity_rows`, `zero_fill_rows`, `repaired_tiles`, `zero_filled_tiles`, `ignored_newer_tile_packets`, `parity_fallback_rows`, and `duplicate_selected_tile_cells`. Count ignored-newer tiles as in-window `TILE` packets whose revision is higher than the selected row parity revision. Count parity fallback rows when a CRC-bad parity packet had a higher revision, or the same revision and higher seq, than the selected valid parity. Count duplicate selected tile cells when more than one in-window `TILE` packet exists at the selected row revision.

`frame_order_digest` is the SHA-256 of one newline-terminated ASCII line per frame: `index|capture_ms|cutoff_ms|frame_sha256|repaired_count|zero_filled_count|comma-separated row actions`. Whitespace in JSON is not important.
