The bundle contains release-frame metadata plus temporal design records. Render every frame independently on a 32 by 32 pixel canvas.

Files:

- `releases.json`: array of frames in atlas order. Each frame has `id`, `design_time`, `export_at`, and `background_swatch`.
- `palette.csv`: color records with `record_id,swatch_id,revision,published_at,effective_from,status,r,g,b`.
- `placements.ndjson`: layer records with `record_id,entity,revision,published_at,effective_from,status,frames,symbol,x,y,z,swatch,opacity,transform`. Optional `blend` is one of `over`, `erase`, `multiply`, or `screen`; when omitted, treat as `over`. Candidate records also have `choice_group` and integer `choice_weight`.
- `symbols.ndjson`: alpha masks. Each row has `id`, `width`, `height`, and `rows`. Mask row characters are decimal digits `0` through `9`; `0` is transparent and `9` is full mask alpha. A row may either be a plain character string or an `rle:` row. An `rle:` row contains space-separated runs in `COUNTxDIGIT` form, such as `rle:3x0 4x9 1x0`; expand it to exactly `width` characters before further use. A symbol may optionally declare `base` (another symbol id) and `inherit_transform` (one of the supported transforms; if omitted, treat as `none`).
- `choices.json` is optional. When present, it is an array of selection rules with `group`, `frames`, `choose`, `modulus`, and `target_mod`.

Times are UTC ISO-8601 strings ending in `Z`. For a frame, a palette record or placement record is eligible only when `published_at <= export_at` and `effective_from <= design_time`. Do not use records published after the frame export time, even if their effective date is earlier.

Resolve each swatch independently. Among eligible records for the same `swatch_id`, choose the record with the highest numeric `revision`; break ties by later `published_at`; break any remaining tie by lexicographically smaller `record_id`. If the chosen record has `status` other than `active`, that swatch is unavailable.

Resolve each placement entity independently. The `frames` field is a comma-separated selector list. `*` includes every frame, a bare frame id includes that id, and a token prefixed by `!` or `-` excludes that id. Apply selectors from left to right, starting from not included; later selectors override earlier selectors. Among eligible placement records for the same `entity` that apply to the frame, choose the record with the highest numeric `revision`; break ties by later `published_at`; break any remaining tie by lexicographically smaller `record_id`. If the chosen record has `status` `revoked`, do not draw that entity for the frame.

Records with `status` `candidate` are not drawn unless selected by a matching `choices.json` rule. For each frame, process matching choice rules in the order they appear in `choices.json`. For each rule whose `frames` selector includes that frame, collect resolved candidate records with the same `choice_group` that have not already been selected by an earlier matching choice rule for that frame. Select exactly `choose` candidates whose `choice_weight` sum has residue `target_mod` modulo `modulus`. The bundle is invalid if no exact subset exists. If multiple exact subsets exist, choose the subset whose sorted entity-id list is lexicographically smallest. A candidate selected by an earlier rule is not available to later rules in the same frame and is drawn only once. Candidate selections do not carry over between frames. Draw only the selected candidate records. Candidate groups are a scalability requirement for the reusable renderer: verifier bundles may include a choice group with 34 resolved candidates, `choose` 17, and a 20 second subprocess budget for that bundle. A renderer must not depend on enumerating every `choose`-subset.

The resolved mask for a symbol is the digit grid that will later receive the placement transform. If the symbol has no `base`, expand its `rows` to `width` by `height` digits; those rows must not contain `.`. If the symbol has a `base`, take the fully resolved mask of that base, apply this symbol's `inherit_transform`, then combine the result with this symbol's own expanded `rows`. In that combination, a digit character replaces the inherited digit at that cell and a `.` character keeps the inherited digit. After `inherit_transform`, the inherited mask dimensions must equal this symbol's `width` and `height`. Inheritance may nest through repeated `base` links. A symbol must not appear in its own base chain. Expand local `rows` from plain or `rle:` form before combining; each expanded character must be a digit, or `.` when `base` is set. `rle:` runs may encode `.` as the run character, for example `rle:3x. 1x9`.

Fill the canvas with the resolved `background_swatch`. Draw active placements sorted by ascending numeric `z`, then lexicographic `entity`. Resolve the placement's symbol mask first, then apply the placement `transform` list before drawing. The `transform` field is a comma-separated list of supported transforms applied left to right; an omitted or empty field means `none`. Supported transform tokens are `none`, `rot90`, `rot180`, `rot270`, `flip_x`, and `flip_y`. `rot90` is 90 degrees clockwise; `rot180` is 180 degrees; `rot270` is 270 degrees clockwise; `flip_x` mirrors across the vertical axis by reversing each row; `flip_y` mirrors across the horizontal axis by reversing row order; `none` leaves rows unchanged. Coordinates `x,y` give the fully transformed mask's top-left corner. Pixels outside the canvas are clipped.

For every covered destination pixel, let `m` be the mask digit at that transformed mask pixel and `o` be the placement opacity integer from `0` to `255`. The integer alpha numerator is `a = m * o` and the denominator is `2295`. Let `dst` be the current canvas channel and let `src` be the placement swatch channel, except for `erase`, which uses the frame's resolved background channel as `src` and ignores the placement swatch for blending. Blend each channel with half-up rounding according to `blend`:

- `over`: `out = floor((src * a + dst * (2295 - a) + 1147) / 2295)`
- `erase`: same formula as `over`, but with background as `src`
- `multiply`: `out = floor((dst * (2295 - a) * 255 + dst * src * a + 1147 * 255) / (2295 * 255))`
- `screen`: `out = floor((255 * 2295 - (255 - dst) * (255 * 2295 - src * a) // 255 + 1147) / 2295)`

Write `atlas.ppm` as ASCII PPM `P3`, width `32 * number_of_releases`, height `32`, max value `255`, with release frames placed left to right in listed order.

For each frame in `report.json`, `clipped_mask_pixels` and `overpainted_mask_pixels` are audit counters, not final-image pixel counts. `clipped_mask_pixels` counts every transformed source-mask pixel with digit other than `0` after clipping to the 32 by 32 canvas and before blending. If two drawn placements cover the same destination pixel, count both source-mask pixels. `overpainted_mask_pixels` is sampled at the same moment: count that nonzero clipped source-mask pixel only when its destination pixel already differs from the frame's resolved background color immediately before the pixel is blended.
