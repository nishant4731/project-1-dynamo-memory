Rebuild the mono master from the failed AFR transfer in `/app/transfer`, and leave a reusable recovery program at `/app/recover_afr.py`.

The visible inputs are `/app/transfer/ledger.csv`, `/app/transfer/FORMAT.md`, and the block files under `/app/transfer/blocks`. The ledger is authoritative: ignore any block file not named by an approved ledger row, ignore rows whose `state` is not `approved`, and decode each data row according to its AFR header codec and `/app/transfer/FORMAT.md`. Discard an approved row if its decoded canonical PCM bytes do not match that row's `decoded_sha256`.

For each `(stripe, slot)` data position, use the verified approved data row with the highest numeric `revision`. Do not assume a fixed number of slots per stripe; derive the data slots present in each transfer from the approved ledger data rows and the parity metadata. If one data slot in a stripe has no verified approved row, recover it from that stripe's approved `xor_parity` row. If two data slots in a stripe have no verified approved rows, recover both by solving the bytewise equations supplied by that stripe's approved `xor_parity` and `gf256_parity` rows. The GF(256) polynomial and slot coefficients are defined in `/app/transfer/FORMAT.md`.

Assemble the restored master by increasing `start_sample`. Write `/app/restored_master.wav` as mono, 16-bit little-endian PCM WAV at 16000 Hz. It must contain only the restored audio frames, with no leading or trailing padding. The same recovery logic must also be available as `python3 /app/recover_afr.py <transfer_dir> <wav_out> <report_out>`, where `<transfer_dir>` is another directory with the same `ledger.csv`, `FORMAT.md`, and `blocks` layout.

Also write `/app/recovery_report.json` as a JSON object with exactly these keys:
`sample_rate`, `sample_count`, `pcm_sha256`, `recovered`, and `selected_blocks`.
`sample_rate` is `16000`. `sample_count` is the number of samples in the WAV. `pcm_sha256` is the SHA-256 hex digest of the WAV's raw PCM frame bytes, not of the whole WAV file. `recovered` is a list sorted by `(stripe, slot)`; each item has integer `stripe`, integer `slot`, and `method` set to `xor_parity` for one-slot recovery or `gf256_dual_parity` for two-slot recovery. `selected_blocks` is sorted by output order; each item has integer `stripe`, integer `slot`, `block_id`, and `source`. For a block selected directly from the ledger, use its ledger `block_id` and relative ledger `path` as `source`. For one-slot parity recovery, use `block_id` set to `recovered` and `source` set to `parity:xor`. For two-slot parity recovery, use `block_id` set to `recovered` and `source` set to `parity:xor+gf256`.
