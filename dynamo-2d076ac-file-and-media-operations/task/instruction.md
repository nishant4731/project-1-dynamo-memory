Recover the current loop masters from the damaged RIFF/WAVE files in `/app/data/session`. Write a reusable Python 3 program at `/app/recover_session.py`, then use it on that directory to produce `/app/recovered_manifest.json` and repaired WAV files in `/app/recovered`.

Your program must accept three arguments: `python3 /app/recover_session.py INPUT_DIR OUTPUT_JSON OUTPUT_DIR`. The verifier will also run it on another directory with the same file format, so do not hardcode the shipped file names or track names.

Each input directory contains a `release_plan.json`; for the shipped data this is `/app/data/session/release_plan.json`. It contains `cutoff`, `sample_rate`, and `required_tracks`. Use that cutoff instead of the current date. Candidate audio files are RIFF `WAVE` containers with PCM mono 16-bit little-endian audio at the plan sample rate. Do not trust the file name or the RIFF size field. Walk chunks in file order until EOF, honoring the RIFF rule that odd-sized chunks have one pad byte. Concatenate every `data` chunk in that file to form the sample stream. Ignore unknown chunks except for their padding.

Every selectable file has one `dync` chunk containing UTF-8 JSON with `track_id`, `take_id`, `revision`, `effective_from`, `published_at`, `status`, `bundle_id`, and `bundle_revision`. A take is eligible only when `status` is `active`, its `track_id` is in the plan's `required_tracks`, `effective_from` is at or before the plan cutoff, and `published_at` is at or before that same cutoff. Apply eligible repairs before deciding whether a take is usable: a take with any remaining `-32768` sentinel sample is not usable for bundle completeness or output.

Select one global release bundle first: a bundle is complete only if it has at least one eligible usable take for every required track. For bundle comparison and for the manifest, a bundle's `bundle_revision` is the maximum `bundle_revision` value among the eligible usable takes selected for that bundle's required tracks. Choose the complete bundle with highest `bundle_revision`, then latest selected-take `published_at` after choosing each track's best take inside that bundle, then lexicographically greatest `bundle_id`. Within the selected bundle, choose one take per track by highest `revision`, then latest `published_at`, then lexicographically greatest `take_id`. Later-published files, void files, unrepaired takes, incomplete newer bundles, older revisions, and file names are decoys.

Some files contain one or more `rpr ` chunks. Each is UTF-8 JSON: a list of repairs with `offset`, `values`, and `published_at`. A repair applies only when its `published_at` is at or before the cutoff. It overwrites samples starting at zero-based `offset`; if multiple repairs overwrite the same sample, keep the value from the latest eligible repair. If two eligible repairs for the same sample have the same `published_at`, keep the first value encountered while walking `rpr ` chunks in file order and then entries in list order. Samples with the sentinel value `-32768` must be repaired before output.

Some files contain a `loop` chunk with UTF-8 JSON containing integer `start` and `end` sample offsets. Include those offsets in the manifest for the selected take.

The manifest at `/app/recovered_manifest.json` must be JSON with exactly these top-level keys: `cutoff`, `sample_rate`, `bundle_id`, `bundle_revision`, and `tracks`. Use compact deterministic values copied from the selected bundle and plan: for the shipped data, `cutoff` is `2026-07-01T00:00:00Z`, `sample_rate` is `8000`, and `tracks` is sorted by `track_id`. Each track object must contain `track_id`, `take_id`, `revision`, `duration_samples`, `loop_start`, `loop_end`, `peak_abs`, `rms`, and `sha256_pcm`. `rms` is `sqrt(mean(sample^2))` over repaired signed samples, rounded to three decimals. `sha256_pcm` is the lowercase SHA-256 hex digest of the repaired raw PCM bytes.

For each selected track, write `/app/recovered/<track_id>.wav` as a clean standard RIFF/WAVE file containing only a `fmt ` chunk and one `data` chunk with the repaired PCM. For the shipped data, the required files are `/app/recovered/bass.wav`, `/app/recovered/drums.wav`, and `/app/recovered/lead.wav`.
