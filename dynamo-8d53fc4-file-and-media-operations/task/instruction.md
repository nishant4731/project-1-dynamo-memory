Create executable `/app/recover_cues.py`. The verifier runs `python3 /app/recover_cues.py <session_dir> <output_json>`. Practice session: `/app/sessions/shoreline`. The tool must work for other same-layout sessions. Each session has `tracks/*.wav`, `events.tsv`, `calibration.tsv`, and optional `conform.json`.

Every WAV is mono, 16-bit little-endian PCM at 8000 Hz, but the RIFF layout may insert `fact`, `LIST`, or `JUNK` chunks before `data`. Always locate the `data` chunk and read PCM only from it. The first 512 PCM samples are a slate. Starting at sample 64, read 16 cells spaced 24 samples apart. A cell is bit `1` when its sample is positive and bit `0` when negative; a zero-valued slate cell is invalid. The first four bits must be `1011`; files with an invalid cell or any other magic are bad-slate files and are not clips. The next four bits are an unsigned lane number, and the final eight bits are an unsigned cue number. The audio payload starts after sample 511 of that PCM stream.

`events.tsv` has tab-separated columns `id`, `file`, `kind`, `value`, `seq`, and `revokes`. Row IDs are session-global across `events.tsv` and `calibration.tsv`: first collect one revoked-ID set from the pipe-separated `revokes` field of every row in both TSV files, then filter both tables with that same set. A row in either TSV can revoke a row in either TSV. For each remaining event `file` and `kind`, use the row with the largest integer `seq`; break seq ties by the lexicographically largest `id`. Kinds are `device`, `logged_start_ms`, `trim_left_ms`, `trim_right_ms`, `mute`, `rate_ppm`, and `pad_left_ms`. Missing trims, `rate_ppm`, and `pad_left_ms` are zero. Missing mute means not muted. A file is muted only when the selected `mute` value is `1`.

`calibration.tsv` has columns `id`, `device`, `logged_ms`, `absolute_ms`, `seq`, and `revokes`, and uses the same session-global revoked-ID set. For each device, compute each active anchor delta as `absolute_ms - logged_ms`; the device offset is the median delta, using the lower middle value when the count is even.

For every regular `.wav` in `tracks/`, include it only when it has a valid slate, is not muted, has selected `device` and `logged_start_ms` events, and the selected device has a calibration offset. Exclusion precedence is fixed: bad-slate files are counted only under `bad_slate_files` / `zero_slate_files` and are never also counted as muted, missing-event, or uncalibrated, even when matching event rows exist. For each included file compute a provisional clip:

- Base `cue_id` is `L<lane>-C<cue>` with lane width 2 and cue width 3.
- `timeline_ms = logged_start_ms + (logged_start_ms * rate_ppm) // 1000000`.
- Provisional `start_ms = timeline_ms + device_offset + trim_left_ms`.
- `duration_ms = max(0, payload_duration_ms - trim_left_ms - trim_right_ms)`.
- Build the trimmed PCM payload bytes after left/right trims at 8000 Hz / 16-bit mono (`trim_ms * 16` bytes per side). When trims consume or cross the whole payload, the trimmed payload is empty.
- Let `pad_bytes = pad_left_ms * 16`.

After all provisional clips exist, if a base `cue_id` appears on more than one included clip, rewrite those clips' `cue_id` values to `L<lane>-C<cue>-R<nn>` where `<nn>` is the 1-based ordinal with width 2 among that base-id group ordered by provisional `start_ms`, then `file`. Leave unique base ids unchanged. `duplicate_cue_ids` counts how many distinct base cue ids required these ordinals.

If `conform.json` exists, it is a JSON object with positive integer `mod` and integer `target_residue` in `0 .. mod-1`. Let `S` be the smallest integer in `0 .. mod-1` such that `(sum(provisional start_ms) + len(clips) * S) % mod == target_residue`. If no such `S` exists, use `S = 0`. If `conform.json` is absent, `S = 0`. Add `S` to every clip's `start_ms`. Then set each clip's `sha16` to the first 16 lowercase hex characters of SHA-256 over: little-endian signed 32-bit `start_ms`, then `b"\x00" * pad_bytes`, then the trimmed payload. Padding, ordinals, and `S` affect hashing/naming as specified; they never change `duration_ms` or inclusion.

Write `<output_json>` as JSON with keys `session`, `clips`, and `report`. `session` is the session directory basename. `clips` is sorted by final `start_ms`, then `cue_id`, then `file`; each clip has `file`, `cue_id`, `start_ms`, `duration_ms`, and `sha16`. `report` has integer fields `files_scanned`, `files_included`, `muted_files`, `bad_slate_files`, `missing_event_files`, `uncalibrated_files`, `zero_slate_files`, `empty_trimmed_files`, `duplicate_cue_ids`, `rate_adjusted_files`, `padded_hash_files`, `conform_shift_ms`, `revoked_rows`, `active_event_rows`, `active_calibration_rows`, `revoking_rows`, plus `device_offsets_ms` and `lane_counts`. `muted_files` counts exclusions from selected mute `1`. `bad_slate_files` counts bad-slate WAVs; `zero_slate_files` is the zero-cell subset. `missing_event_files` counts otherwise includable files missing selected `device` or `logged_start_ms`. `uncalibrated_files` counts otherwise includable files whose device has no offset. `empty_trimmed_files` counts included empty trimmed payloads. `rate_adjusted_files` / `padded_hash_files` count included clips with nonzero `rate_ppm` / positive `pad_left_ms`. `revoked_rows` is the distinct revoked-ID count; `active_event_rows` / `active_calibration_rows` count non-revoked rows in each TSV; `revoking_rows` counts non-revoked rows in either TSV with nonempty `revokes`. `device_offsets_ms` maps device to offset. `lane_counts` maps two-digit slate lanes to included counts, ignoring `-R` ordinals.

After writing `<output_json>`, delete `<session_dir>/calibration.tsv`. Do not delete `events.tsv`, `conform.json`, or any WAV files.
