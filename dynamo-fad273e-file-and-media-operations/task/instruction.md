Recover the approved audio masters from `/app/data/session` and write them under `/app/recovered_audio`. Also write a reusable Python 3 recovery program at `/app/recovered_audio/recover_session.py`; when run with `python3 /app/recovered_audio/recover_session.py`, it must read `SESSION_DIR` and `OUTPUT_DIR` environment variables, defaulting to `/app/data/session` and `/app/recovered_audio`, and perform the same recovery for any session that follows this format.

The session manifest is `/app/data/session/session_manifest.json`; the release ledger is `/app/data/session/release_ledger.csv`. Use the manifest cutoff time. Ledger rows with `timestamp_utc` later than the cutoff do not exist for this recovery. Process remaining ledger rows by ascending `timestamp_utc`, preserving file order for equal timestamps. The ledger is stateful: a `release` marks that exact `(asset_id, revision)` pair released even if that same pair was revoked earlier, and a later `revoke` marks only that exact `(asset_id, revision)` revoked (other revisions of the same asset are unchanged). For each `asset_id`, the active master is the maximum revision number among revisions whose final state at the cutoff is released — not the revision named by the chronologically latest `release` row, and not an asset-wide clear on revoke. Example: if revision 5 is released, then revision 3 is released later, and both remain released at the cutoff, the active master is revision 5. Do not output revoked assets or assets released only after the cutoff.

Each manifest fragment is a payload-only packet. Validate every packet against its `payload_sha256`. For an `xor_payload_bytes` parity group, if exactly one member is missing or has a bad hash, recover that member by XORing the parity payload with the other member payloads byte by byte; the parity payload itself must match its manifest hash. For a `gf256_linear_payloads` parity group, `members` lists equal-length payloads and each `parity_rows` entry has `path`, `payload_sha256`, and `coefficients`; `path` is the parity payload file, `payload_sha256` validates that parity payload, and `coefficients` is in the same order as `members` with one coefficient per member. The field is GF(256) with reduction polynomial `0x11b`; byte addition is XOR, and multiplication is carryless multiplication modulo `0x11b`. If `k` members are missing or bad and at least `k` parity rows are present, use the earliest `k` parity rows in manifest order whose coefficient submatrix for the missing members is nonsingular, solve those equations independently at every byte offset, then validate the recovered payload hashes.

Decode fragment codecs into signed 16-bit PCM frames, then concatenate fragments for each active asset by ascending `sequence`. `PCM16` is little-endian interleaved samples. `DLT16` stores little-endian signed deltas per channel; the first frame is absolute and later frames add the delta to the previous sample in the same channel. `BDL16` is also little-endian signed deltas per channel, but it resets at fixed-size frame blocks: the manifest field `block_size` gives the block length, the first frame of each block is absolute, and later frames add the delta to the previous sample in the same channel within that block. `MS16` stores stereo little-endian `(mid, side)` pairs, where `mid = floor((left + right) / 2)` and `side = left - right`; recover `left = mid + ceil(side / 2)` and `right = left - side`.

Write one 16-bit PCM WAV file per active asset at `/app/recovered_audio/<asset_id>.wav`. Use the manifest sample rate and channel count. Also write `/app/recovered_audio/cue_sheet.json` as a JSON object with exactly:

The reusable recovery program must remain efficient when a session's `delivery_mix` contains many items with large `offset_candidates` lists or a large `residue_mod`; do not assume the visible session's candidate counts or modulus are maximums, and do not use memory proportional to `residue_mod` because it may be near a 32-bit value.
