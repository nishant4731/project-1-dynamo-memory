Recover the canonical video master for the session described by `/app/archive/session.json`. The packet ledger is `/app/archive/packets.jsonl`; packet `path` values are absolute paths under `/app/archive/media`.

Create two outputs: `/app/recovered_master.ppm` and `/app/recovery_report.json`.

Use only packets whose `program_id`, `stream`, `dimensions`, and `frame_index` match the session, and whose `capture_ts` is less than or equal to the session `freeze_ts`. Packets after the freeze are ignored completely, including their `supersedes` claims. Ignore packets for other streams or programs.

For `packet_type: "frame"` records, read the P6 PPM file at `path`, decode its raw RGB pixel bytes, and discard the packet unless the decoded width and height match the session and `sha256(pixel_bytes)` equals the record's `content_sha256`. After this validity check, apply supersession only among still-eligible frame packets: if an eligible packet names another eligible frame packet in `supersedes`, the named packet is no longer a candidate. For each frame with at least one remaining direct frame candidate, choose the candidate with highest `version`, then latest `capture_ts`, then lexicographically largest `packet_id`.

If a frame has no valid direct frame candidate, recover it from an eligible `packet_type: "xor_parity"` record. The parity blob at `path` is the bytewise XOR of the target frame's RGB pixel bytes and the already recovered partner frame named by `partner_frame_index`. Verify `sha256(parity_blob)` equals `parity_sha256`, XOR it with the partner's pixel bytes, and keep the result only if `sha256(recovered_target_bytes)` equals `target_sha256`. If several parity packets are valid for the same target frame, use highest `version`, then latest `capture_ts`, then lexicographically largest `packet_id`.

`/app/recovered_master.ppm` must be a binary P6 PPM sprite sheet with width `frame_width * frame_count`, height `frame_height`, max value `255`, and no padding. Place frame 0 at the left, then frame 1, continuing in increasing `frame_index` order.

`/app/recovery_report.json` must be UTF-8 JSON with exactly these top-level keys: `program_id`, `freeze_ts`, `frame_width`, `frame_height`, `frame_count`, `frames`, `sprite_sha256`, and `sprite_pixel_sha256`. `sprite_sha256` is the SHA-256 hex digest of the complete `/app/recovered_master.ppm` file bytes. `sprite_pixel_sha256` is the SHA-256 hex digest of the concatenated sprite RGB pixel bytes only. `frames` must contain one object per frame in increasing `frame_index` order. Direct frame objects must have exactly `frame_index`, `method`, `packet_id`, and `sha256`, with `method` equal to `"direct"`. Parity-recovered frame objects must have exactly `frame_index`, `method`, `packet_id`, `partner_frame_index`, and `sha256`, with `method` equal to `"xor_parity"`. Frame `sha256` values are over that frame's RGB pixel bytes only.
