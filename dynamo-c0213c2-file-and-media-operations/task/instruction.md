Create an executable Python 3 program at `/app/atlas_repair.py`. It accepts exactly one session-directory argument, repairs the session in place, and for the shipped input writes `/app/session/recovered/atlas.ppm` and `/app/session/recovered/report.json`. It must also work for other sessions with the same `manifest.json`, `FORMAT_NOTES.txt`, and `evidence/` layout. Treat `FORMAT_NOTES.txt` as part of the format contract.

Inputs use binary Netpbm `P6` RGB PPM or `P5` grayscale PGM with max value 255. TSV paths are session-relative; empty, absolute, `..`, or symlink-component paths fail the path stage. Safe missing files fail the digest/hash stage. SHA-256 fields are lowercase raw-byte digests.

Derive each device offset `(dx, dy)` from valid anchors: parsed row, safe path, digest match, 1x1 PPM, contribution `(world_x - seen_x, world_y - seen_y)`. Pick the offset by largest count, then largest anchor `seq`, smaller `dx`, smaller `dy`. Report only chosen-offset anchor rows, with `anchor_seqs` sorted ascending.

After offsets, derive each device color profile from `evidence/calibration.tsv`. A valid row parses, has safe path and digest match, decodes as a 1x1 PPM raw swatch, and has `true_r`, `true_g`, `true_b` in `0..255`. Try candidates by lexicographic `perm` among `bgr`, `brg`, `gbr`, `grb`, `rbg`, `rgb`; then lexicographic `gain_nums`, each in `{1,2,3,4,5}`; then lexicographic `biases`, each in `{-36,-24,-12,0,12,24,36}`. A candidate maps `corrected[channel] = clamp((raw[perm[channel]] * gain_nums[channel]) // 3 + biases[channel], 0, 255)`. Use the first candidate matching all valid rows for the device; if none match, use identity `perm=rgb`, `gain_nums=[3,3,3]`, `biases=[0,0,0]`. Apply the profile to packet RGB pixels after geometry and before mask blending.

Validate packet rows once, rejecting at the first failing stage in this order: `parse`, `bad_asset_path`, `bad_asset_hash`, `bad_mask_path`, `bad_mask_hash`, `bad_image`, `bad_mask`, `bad_transform`, `bad_opacity`, `missing_offset`, `dimension_mismatch`. Render valid packets by `(z, seq)`. Valid transforms are `id`, `r90`, `r180`, `r270`, `fh`, `fh_r90`, `fh_r180`, `fh_r270`; `fh` applies before rotation. Rotations are clockwise in image coordinates. For a `W` by `H` image after any flip: `r90` sends source `(x, y)` to `(H - 1 - y, x)` on `H` by `W`; `r180` sends it to `(W - 1 - x, H - 1 - y)`; `r270` sends it to `(y, W - 1 - x)` on `H` by `W`. Packet origin is `(x + dx, y + dy)`.

Before each valid packet, apply valid taps whose `before_seq` equals that packet `seq`, in TSV order. A valid tap parses, names a valid packet seq, has positive `width`, `height`, `gain_num`, `gain_den`, and has `roll` in `{0,1,2}`. A parsed integer `before_seq` that names no valid packet rejects as `orphan`; other tap parse/range failures reject as `parse`, with `before_seq:null` when unparseable. Each tap reads a fresh snapshot captured immediately before that tap, so earlier same-packet taps are visible to later taps, but a tap cannot read its own writes. For each in-bounds source/destination pair, write `clamp((source[(channel + roll) % 3] * gain_num) // gain_den + bias, 0, 255)`; out-of-bounds pairs count as tap-clipped pixels.

Packet pixels use the transformed mask. Off-canvas destinations count clipped. In-bounds mask values give `alpha = mask * opacity // 255`; alpha zero counts transparent and writes nothing. Otherwise blend `(src * alpha + dst * (255 - alpha)) // 255`. Count overwrite when the pre-blend destination differs from the manifest background color.

After success, remove the session's `evidence/` directory. `atlas.ppm` is canonical `P6\nWIDTH HEIGHT\n255\n` plus raster. `report.json` is a JSON object, no extra top-level keys, with `version`, `canvas`, `device_offsets`, `color_profiles`, `rendered_packets`, `rejected_packets`, `applied_taps`, `rejected_taps`, and `counters`; member order and whitespace do not matter. `version` is integer `1`; all numeric values are JSON integers. `canvas` has `width`, `height`, `sha256` of `atlas.ppm`. `device_offsets` is device-ordered entries with `device`, `dx`, `dy`, `anchor_seqs`. `color_profiles` is device-ordered entries with `device`, `perm`, `gain_nums`, `biases`, `calibration_seqs` sorted ascending. `rendered_packets` is the packet seq array. Rejection entries contain `seq` or `null` plus `reason`. Applied taps contain `before_seq`, `tag`, `pixels` for in-bounds writes; rejected taps contain `before_seq`, `tag`, `reason`. `counters` contains `anchor_rows_used`, `bad_anchor_rows`, `calibration_rows_used`, `bad_calibration_rows`, `rendered_packets`, `rejected_packets`, `applied_taps`, `rejected_taps`, `blended_pixels`, `transparent_pixels`, `clipped_pixels`, `overwritten_pixels`, `tap_pixels`, and `tap_clipped_pixels`. `anchor_rows_used` equals the total chosen-offset anchor seq count, excluding valid non-chosen offsets; `calibration_rows_used` equals the total reported calibration seq count.
