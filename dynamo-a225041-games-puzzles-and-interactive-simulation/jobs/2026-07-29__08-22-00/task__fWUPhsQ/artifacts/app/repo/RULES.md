# Signal Bastion engine contract

`bastion.engine.resolve_round(state, commands)` is pure: it returns a new state and never mutates either argument. A state has `size`, `round`, and `units`. Unit positions are unique integers on a ring `0..size-1`. `registered` is the authoritative stable unit order; identifiers are labels and must never determine priority. The returned `units` array contains survivors in ascending `registered` order, regardless of input-array order.

For one round, first choose at most one command per living unit. A start snapshot may contain units with `hp <= 0`; they are nonliving, their commands are ignored, they cannot be combat targets, and they are removed after combat. Ignore unknown actors and malformed commands before duplicate selection; a malformed higher-nonce duplicate cannot suppress a lower-nonce valid command. Every command requires a `nonce` whose type is exactly integer (booleans are not integers here). When an actor has multiple nonmalformed commands, choose the greatest `nonce`; if tied, the later command in the input array wins. Supported commands are `wait`; `move` with `delta` exactly integer `-1` or `1`; `blink` with `choices`, a nonempty array of distinct exact integer positions in `0..size-1`; `attack` with a `target` whose type is exactly string and that equals the `id` of some unit present in the start-snapshot `units` array (including units that already have `hp <= 0`); and `pulse`. Any missing `target`, non-string `target` (including booleans and integers), or string that names no start-snapshot unit makes that attack command malformed. Command legality uses the complete start-of-round unit snapshot: a rooted unit cannot move or blink, blink requires `energy >= 1`, and pulse requires `energy >= 2` and `cooldown == 0`. Cooldown and status duration do not decrement before legality.

Resolve legal blinks before ordinary movement. A blinker may be assigned only a position listed in its `choices` that was empty in the complete start snapshot; another unit's origin is not a candidate even when that unit also blinks. Assign at most one position per blinker and at most one blinker per position. Among all assignments, first maximize the number assigned, then minimize the sum of each assigned position's zero-based index in that actor's `choices`. If still tied, use the lexicographically smallest vector of assigned positions for blink actors in ascending registration order, representing an unmatched actor by sentinel `size`. Valid states can contain at least 80 legal blink actors with overlapping choices, so exhaustive subset/permutation search is not acceptable. Apply successful blinks simultaneously; each successful blinker spends 1 energy, while an unmatched blinker spends nothing.

Then resolve ordinary moves simultaneously on the ring using occupancy after successful blinks. Multiple movers naming one destination all fail. A unique chain ending at a cell empty after blinking shifts successfully. A chain ending at a nonmoving or failed occupant fails. A directed movement cycle of length at least three rotates successfully. A two-unit swap succeeds only when both units have the same team. Apply no partial movement from a failed chain. Valid states can contain at least 1,500 units in one dependency chain, so ordinary movement resolution must not depend on the host language's recursion-depth limit.

Combat uses post-movement positions, but every unit alive at round start executes its selected legal combat command even if the same round defeats it. Ring adjacency is minimum cyclic distance one. `attack` deals 2 damage to its named target only when that target's `id` is in the living-start set (`hp > 0` in the start snapshot) and the attacker is adjacent after movement; a well-formed attack that names a start-snapshot unit already nonliving at round start is legal for command selection but deals no damage and emits no damage event. `pulse` deals 1 damage to every adjacent enemy that is in the living-start set after movement, spends 2 energy, and sets cooldown to 3; adjacent enemies that were already nonliving at round start take no pulse damage. Aggregate all damage per target before applying it: shield absorbs `min(shield,total_damage)` once, then remaining damage reduces HP. Remove units whose resulting HP is at most zero only after all combat is accumulated.

After combat, every surviving unit gains 1 energy up to 5 after any successful blink or pulse cost. A unit that did not pulse gets cooldown `max(0, old_cooldown-1)`; a pulsing unit keeps cooldown 3. Root duration is an integer `rooted`; it becomes `max(0, old_rooted-1)` at round end, so `rooted=1` still blocks movement and blinking in that round. Units that were already nonliving at round start are still removed in the defeat phase and emit defeat events. Increment `round` once.

The returned `events` array is rebuilt for the round. Emit successful blink events first in registration order, then successful ordinary movement events in registration order, then attack/pulse damage events in acting-unit registration order (pulse targets in target registration order), then defeat events in defeated-unit registration order. Blink events are `{"actor":id,"from":old_position,"kind":"blink","to":new_position}`; other event objects use exactly the shapes produced by the reference API in the visible tests. Omit failed/ignored actions from events.

## Cooperative route planner

`bastion.planner.plan_routes(grid, agents)` computes one globally optimal synchronous schedule and does not mutate either input. Valid `grid` values are nonempty rectangular arrays of equal-length strings containing only `.` for an open cell and `#` for a wall. Each valid agent has exactly `id`, `start`, `goal`, and `priority`; identifiers are unique strings, priorities are unique exact integers, and starts and goals are distinct open `[row,column]` cells. Inputs are guaranteed to have a solution. Return agents in ascending priority order regardless of input order.

At every tick an agent either waits or moves one cell orthogonally through open cells. Once an agent first reaches its goal it must remain there. A schedule is invalid when two agents occupy one cell at the same tick or when two agents traverse the same edge in opposite directions during one tick. The path for each agent includes its start at tick zero and one position for every later tick, padded by goal waits through the common makespan.

Choose the valid schedule by three objectives in order. First minimize `makespan`, the number of ticks until every agent is at its goal. Among those schedules minimize `sum_cost`, the sum over agents of the first tick at which each reaches its goal. If still tied, compare the complete joint position trace lexicographically: at tick 1, then tick 2, and so on, list each agent's `(row,column)` in ascending priority order and flatten those integer pairs; choose the smallest flattened sequence. Cases may contain at least six mutually blocking agents on an 8-by-8 grid, so planning agents independently is not sufficient.

Return exactly `{"makespan":makespan,"sum_cost":sum_cost,"paths":paths}` where each path entry is `{"id":id,"path":[[row,column],...]}` in ascending priority order and every path has exactly `makespan+1` positions.

## Relay stabilizer

`bastion.relay.stabilize_relays(relays, constraints, modulus, target)` chooses one relay option per relay and does not mutate any input. `modulus` is an exact integer greater than one and `target` is an exact integer in `0..modulus-1`. Each relay has exactly `id`, `priority`, and `options`; identifiers are unique strings, priorities are unique exact integers, and each `options` array is nonempty. An option has exactly `id`, `power`, and `phase`; option identifiers are unique within that relay, `power` is a nonnegative exact integer, and `phase` is an exact integer interpreted modulo `modulus`.

Each constraint has exactly `left`, `left_option`, `right`, and `right_option`. It forbids choosing that named option for `left` at the same time as that named option for `right`; the constraint is symmetric regardless of field order. A constraint whose two relay IDs are the same bans that option when the two option IDs are also the same; when the two option IDs differ, the constraint is vacuous because one relay never chooses two options. After coalescing all constraints between the same pair of distinct relays into one undirected edge, every connected component in the relay constraint graph has at most one cycle. Inputs are guaranteed to have at least one complete valid assignment.

For an assignment, `phase` is the sum of chosen option phases modulo `modulus`, `phase_error` is `(target - phase) mod modulus`, and `total_power` is the sum of chosen option powers. Choose the valid assignment by three objectives in order. First minimize `phase_error`; a phase just below the target is better than an equally close phase just above it because the error is a directed forward correction, not absolute distance. Among equal phase errors minimize `total_power`. If still tied, list option identifiers by relay ascending priority and choose the lexicographically smallest string vector.

Return exactly `{"assignments":assignments,"phase":phase,"phase_error":phase_error,"total_power":total_power}`. Each assignment entry is `{"id":relay_id,"option":option_id,"phase":option_phase,"power":option_power}` in ascending relay priority order, using the option's original phase integer. Valid cases may contain at least 70 relays split across many disconnected constraint components, one 70-relay acyclic constraint component, or one 70-relay single-cycle component, with `modulus` near 1,000. Solving each component to its locally best option vector and then combining those local winners is not sufficient, and enumerating all assignments of a large tree or single-cycle component is not acceptable; the directed global residue objective applies after all components are combined.

## Replay controller

`bastion.replay.replay_session(checkpoint, envelopes)` is also pure. `checkpoint` has exactly `state` (a valid round state) and `head` (64 lowercase hexadecimal characters). Each envelope must have exactly `tick`, `revision`, `source`, `base`, `commands`, and `checksum`. `tick` is an integer at least the checkpoint state's round; `revision` is an integer in `0..65535`; booleans are invalid for both; `source` is a string; `base` and `checksum` are 64 lowercase hexadecimal characters; and `commands` is a JSON array. Anything else is malformed.

The envelope payload is UTF-8 canonical JSON of exactly `{"base":base,"commands":commands,"revision":revision,"source":source,"tick":tick}` with keys sorted, separators `(',', ':')`, and `ensure_ascii=True`. `checksum` must equal the lowercase SHA-256 hex digest of those payload bytes. A checksum mismatch is malformed.

Replay starts at the checkpoint state's round and head and never skips a tick. At any state/head and current tick, only structurally valid envelopes whose `base` equals that head are eligible. Collapse equal revisions by keeping the later envelope in input order. Each remaining candidate is certified by the future branch it can actually produce: speculatively execute its commands from that state, derive its canonical next head as described below, and repeat this selection rule at the next tick. Its certification length is one plus the selected child's certification length; it is one when the next tick has no selectable child, including when that next tick is ambiguous. Thus certification follows consecutive ticks and must use each speculative branch's own evolving state and head, not just count frames or compare their declared bases shallowly.

At a selection point, retain only candidates with the greatest certification length. Across their distinct revisions, revision `r` is the unique newest revision only if `(r-s) mod 65536` is strictly less than 32768 for every other retained revision `s`. This makes revision `0` newer than `65535`; a half-range tie or cyclic set has no unique newest revision. The unique newest longest-certified candidate is selected, so a lower revision with a longer authenticated continuation defeats a higher revision with a shorter continuation. If there is no eligible envelope, stop. If the longest-certified candidates have no unique newest revision, mark every eligible envelope at that tick ambiguous and stop.

Execute the chosen envelope with `resolve_round`, which must advance its state from tick `t` to `t+1`. The next head is lowercase SHA-256 of the byte concatenation `b'BST1'`, the 32 bytes decoded from the prior head, the chosen payload bytes, one newline byte, and canonical JSON of the complete returned state (including `events`, using the same JSON settings). Continue at the next tick, so a late correction can invalidate a later branch through its `base`.

Return exactly `{"accepted":accepted,"head":head,"rejected":rejected,"state":state}`. Each accepted entry is `{"index":input_index,"revision":revision,"source":source,"tick":tick}` in replay order. Each rejected entry is `{"index":input_index,"reason":reason}` in original input order. Reasons are: `malformed` for structural/checksum failure; `superseded` for an eligible but unchosen duplicate/revision at a processed tick; `fork` for a valid envelope at an examined tick whose base is not current; `ambiguous` for eligible envelopes at a blocked ambiguous tick; and `unreachable` for every other valid unaccepted envelope after replay stops, including frames after a gap. Wrong-base frames at an otherwise successfully processed tick are still `fork`.

## Effect bytecode

`bastion.vm.run_program(code, variables, gas)` is pure. `code` is an array of exact integers in `0..255`, `variables` is an array of exact integers, and `gas` is a nonnegative exact integer; booleans are invalid. The VM has an initially empty stack limited to 16 values. Every executed opcode, including `HALT`, costs one gas. Values are signed 32-bit two's-complement: every immediate, load, and arithmetic result is normalized to the range `-2147483648..2147483647`. Invalid bytecode, stack underflow/overflow, bad slots/jumps, and exhausted gas raise `VMError`.

Opcodes are `00 HALT`; `01 PUSHI s8`; `02 LOAD u8-slot`; `03 STORE u8-slot`; `04 ADD`; `05 SUB`; `06 MUL`; `07 EQ`; `08 LT`; `09 JZ s8-relative`; `0A JMP s8-relative`; `0B DUP`; `0C SWAP`; and `0D DROP`. Binary operators pop the right operand first and then the left operand. `ADD`, `SUB`, and `MUL` push `left+right`, `left-right`, and `left*right` respectively after signed-32 normalization. `EQ` and `LT` push integer `0` or `1` for `left == right` and `left < right`. `STORE` pops its value. `JZ` pops a condition and jumps only when it is zero; `JMP` always jumps. Signed relative offsets are based at the instruction pointer immediately after the offset byte.

Before consuming gas or executing an opcode, validate `code` as one complete linear instruction stream: every byte in opcode position must be a supported opcode, every immediate-bearing opcode must have its immediate, and the encoded target of every `JZ` and `JMP` must name an opcode byte in that stream. This target rule applies even when a jump is unreachable or a `JZ` condition would make its branch untaken.

Preflight must then validate stack depth and variable-slot operands over the complete control-flow graph reachable from byte zero, beginning at depth zero. Both successors of every reachable `JZ` participate regardless of its eventual runtime condition. `LOAD` and `STORE` slot operands must name an existing variable for every reachable instruction, including instructions only reachable through a runtime-untaken conditional branch. `STORE`, `JZ`, `DUP`, and `DROP` require depths 1, 1, 1, and 1; binary operators and `SWAP` require depth 2. Account for each instruction's pops and pushes, reject any path that underflows or exceeds depth 16, and require every incoming edge to an opcode to have exactly the same stack depth. A reachable non-`HALT` instruction whose fallthrough leaves the stream is invalid. Balanced loops are valid and validation must terminate at a fixed point. `HALT` returns exactly `{"gas":remaining,"halted":True,"ip":ip_after_halt,"stack":stack,"variables":variables}`. Falling off code is invalid.
